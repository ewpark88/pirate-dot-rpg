# 기획: 화물칸 = 골드 금고 용량 (economy, S2)

- 상태: 초안 2026-10-16 — S1 → 사용자 확인 뒤 착수 · 담당: 규칙·표·sim S2 · UI S4 · 연출 S3
- 사용자 지시(S1 중계): "화물칸을 골드를 담을 수 있는 최대 금액을 늘리는 아이템으로 보고 설계를 진행해라. 사용자들이 화물칸 업그레이드 이유를 '골드 최대치를 늘리기 위한 수단'으로 생각해야 한다."
- 함께 확정: 골드 재조정(1f52fc3, 강화 드물고 크게)과 가속 곡선(Lv 8부터, ADR-0011 세이브 v7).

## 목적 (설계서 1장)
- 단순한가: 화물칸 = '골드를 얼마나 담나'. 골드 막대가 차면 강화하거나 화물칸을 키운다 — 할 일이 눈에 보인다.
- 시원한가: 가득 찬 금고를 한 번에 쏟아 큰 강화(외형 단계·선체 도약)를 사는 순간.
- 피로가 없는가: 가득 차도 잃는 것은 '넘친 몫'뿐(보유 골드는 안 줄어듦). 팝업 없음 — 막대가 빨갛게 깜빡일 뿐.
- 공정한가: 오프라인 보상도 용량까지 — 오래 비워도 손해가 정해져 있고, 화물칸을 올리면 그만큼 더 받는다.

## 1. 규칙
1. **보유 골드 상한 = 화물칸 용량** `cargoCapacity(Lv)`. 지금의 화물칸 '골드 배율'은 없앤다(처치 골드 = 적 골드 그대로 × 피버·순풍·보물 바다 등 다른 배수).
2. **가득 차면 더 안 쌓인다**: 처치·보스·상자·돌발 이벤트·도전·유리병·오프라인·광고 골드 모두 `min(보유 + 들어올 몫, 용량)`. 넘친 몫은 버린다.
   - 이벤트 `GoldOverflow(lost)` — 0.5초마다 한 번 묶어서(렌더 '화물칸 가득!' 작은 글자, UI 막대 깜빡).
   - 이미 용량보다 많이 가진 경우(옛 세이브·운영자 지급): 깎지 않는다. 쓰기 전까지 더 안 쌓일 뿐.
3. **용량 곡선**: 그 시점에 사게 되는 '가장 비싼 다음 강화'(대포·선체)의 **2~3회분**을 담는 정도.
   - 화물칸을 안 올리면 큰 강화(외형 단계·마일스톤 도약)를 못 산다 → 화물칸이 '다음 큰 것을 사기 위한 준비'가 된다.
   - **화물칸 자체 비용 = 그 레벨 용량의 50~70%**(표 `costRatio` — 비용을 용량에서 계산). 가득 채운 금고 하나로 화물칸을 올릴 수 있다.
4. **오프라인 보상 = 용량까지**: 받을 몫 = min(계산된 오프라인 골드, 용량 − 보유). 광고 ×2도 같은 상한으로 잘린다.
   - 복귀 화면에 '화물칸이 작아 1.2M 중 0.8M만 실었어요 · 화물칸을 키우면 더 받아요' + 강화 바로가기(S4).
   - 오프라인 상한 시간(8시간)은 그대로 — 둘 중 먼저 닿는 쪽.
5. **환생**: 화물칸 레벨도 다른 부위처럼 처음으로(상점 startParts 대상 아님). 환생 뒤 골드 0.
6. 현상금·피버·이벤트 보상 중 골드인 것은 모두 2번 규칙. 젬·카드·조각은 상한 없음.

## 2. 표 (ship_parts.json `cargo`, 초기값 — sim으로 확정)
```json
{ "id": "cargo", "stat": "capacity", "formula": "exp", "base": 300, "growth": 1.6, "costRatio": 0.6,
  "maxLevel": null, "milestoneEvery": 8, "milestoneMultiplier": 2, "accelLevels": 4, "accelFrom": 8, "visualStages": [1, 4, 7, 12, 20, 34, 54] }
```
- `capacity(Lv) = base × growth^x(Lv) × 2^(Lv ÷ 8)` (x = 가속 곡선의 레벨 자리, 대포·선체와 같은 모양) → 대포·선체 비용 곡선과 같은 기울기로 따라간다.
- `cost(Lv) = capacity(Lv) × costRatio` (costBase·costGrowth 대신). '용량의 60%'가 UI에서 바로 읽힌다.
- 시작 용량 300 = 첫 대포 강화(10) × 30 — 튜토리얼 동안은 가득 찰 일이 없게.
- 외형 단계(갑판 보물상자 → 금고 → 금괴 더미) 문턱은 지금 화물칸 visualStages를 쓴다.

## 3. 엔진·계약 (S2)
- `EconomySystem`/`BattleSystem` 지갑 반영 한 곳(`addGold(s, t, amount)` → 실제 들어간 양, 넘친 양)으로 모은다. 지금 골드를 더하는 곳: 처치(battle _round), 보스, 상자, 광고, 오프라인, 돌발 이벤트, 도전, 유리병, 퀘스트·출석(젬이면 해당 없음), 현상금(골드 보상이 생기면).
- 새 함수 `goldCapacity(GameState s, GameTables t) → BigNum`, `goldRoom(s, t) → BigNum`.
- 이벤트 `GoldOverflow(lost: BigNum)`(0.5초 묶음).
- `BattleView`에 표시값을 따로 두지 않는다(UI가 goldCapacity를 부른다).
- sim: 가상 플레이어 구매 정책에 '금고가 90% 이상 찼는데 살 게 용량을 넘으면 화물칸' 추가. 지표 '금고 가득 시간 비율'(목표 10~25%), '넘친 골드 비율'(목표 ≤ 10%).

## 4. UI (S4) · 연출 (S3)
- 골드 표시 = '현재 / 최대' 막대(80% 이상 노랑, 가득 빨강 깜빡 + 배 탭 화물칸 줄 강조).
- 화물칸 강화 줄: '최대 골드 1.2M → 1.8M' (효과 문구 = 용량).
- 렌더: '화물칸 가득!' 작은 글자(골드가 넘칠 때, 0.5초 묶음), 갑판 보물상자가 넘치는 그림(외형 단계).

## 5. 세이브
- 새 필드 없음(용량은 레벨에서 계산). 옛 세이브: 골드가 용량보다 많으면 그대로(2번 규칙). v7 이행(레벨 ÷3)에 화물칸 포함 — 용량 곡선이 레벨 기준이라 그대로 맞는다.

## 6. 균형 목표 (sim, 20명 × 3시간)
- 진행 그대로: 스테이지 10 6~7분, 40 약 25~30분, 첫 보스 실패 1~3분.
- 강화 간격(첫 회차): s8~12 15~30초, s35~45 50~120초(가속 곡선).
- 오프라인 8시간 = 다음 강화 3~8회 **그리고** 오프라인 몫이 용량에 잘리는 비율 30~60%(화물칸을 올릴 이유).
- 금고 가득 시간 비율 10~25%, 넘친 골드 ≤ 10%.

## 수용 기준
1. 보유 = 용량 − 5에서 처치 골드 20 → 보유 = 용량, `GoldOverflow(15)`.
2. 보유 > 용량(옛 세이브) → 처치 골드 0 들어감, 보유 그대로.
3. 오프라인 계산 1M, 여유 0.4M → 0.4M 지급, 복귀 화면에 '잘린 몫 0.6M'.
4. 화물칸 강화 비용 = 그 레벨 용량 × costRatio.
5. 광고 ×2 오프라인도 용량에서 잘림.
6. sim 6절 목표 통과, balance crews 영향 없음(전투 골드 배율 제거만).

## 결정 필요 (사용자) — 추천 먼저
1. **넘친 골드**: (추천) 버린다 + '화물칸 가득!' 표시 / 다른 안: 넘친 몫의 일부(예: 10%)를 젬·조각으로 바꿔 준다(덜 아프지만 '비워라' 압박이 약해짐).
2. **오프라인 상한**: (추천) 용량까지 — 화물칸을 올릴 가장 큰 이유 / 다른 안: 오프라인은 용량 무시(덜 아프지만 화물칸 동기가 줄어듦).
3. **화물칸 비용**: (추천) 용량의 60% / 50%(더 자주 올림) / 70%(더 아낌).
4. **환생 때 화물칸**: (추천) 처음으로 / 다른 안: 상점 startParts처럼 일부 유지.
