# 스펙: 선원 균형 검사 `game_cli balance crews` (설계서 4.8)

- 상태: 초안 — 승인 대기 · 레인: render(S3, `balance.dart`·`lib/src/balance/`·`test/balance/` — main 8f6bf78에서 넘겨받음) · 설계서 절: 4.8 밸런스 안전장치
- 역할: 표를 **정확하게** 만든다. 벗어난 선원의 수치 조정(skills.json·legends)은 S1 몫.

## 목적
- 공정한가: 같은 등급·레벨이면 40명이 같은 전투력 예산(±10%) 안에 있는지 실제 엔진으로 잰다. 시너지 폭주 조합(상위 1%)도 잡는다.
- 단순한가: 명령 하나, 출력은 마크다운 표 + JSON. 실패면 종료 코드 1.
- 결정론: 시드·시계 고정 → 같은 테이블이면 같은 표.

## 규칙
1. **엔진 그대로**: `CoreEngine`(BattleSystem 포함)을 `ManualClock`·고정 시드로 헤드리스 실행. 장면은 운영자 명령으로만 만든다(엔진 코드 수정 없음):
   `OpSetCrew(id, level)` → `OpSetFleet([id])`(보조 없음) → `OpSetInvincible(on: true)` → `OpJumpStage(S)` → `OpSetWave`/`OpSpawnBoss`.
   배는 기본(1등급·부위 0), 순풍·광고 버프 없음.
2. **등급·레벨**: 대표 레벨 15·30·45·60·75 — 선원 등급은 `rarityOfLevel`(레벨 구간)로 정해지므로 레벨 5개 = 등급 5개. 40명 × 5 = 200칸.
3. **피해량**: 그 선원이 낸 `Damage.amount`의 합(크리티컬 포함). 적이 죽으면 남는 피해(오버킬)가 섞이므로, **적이 죽지 않는 단단한 스테이지 S_tank**(기본 2001)에서 잰다.
   S_tank는 25의 배수가 아니어야 한다 — `regions.bossAt(S)`가 일반 보스(`enemy_ship`, 약점 계열 없음)여야 계열 간 공정(25·50 배수면 중간·해역 보스의 `weakFamilies`가 끼어든다).
   피해 공식에 적 방어가 없어서 스테이지는 피해량에 영향이 없다(이 가정은 테스트로 확인). 측정 중 `Kill`이 나오면 S_tank를 올리라고 실패.
4. **(A) 무리전**: `OpSetWave(count: 12)`로 12마리를 한 번에 내고 60초. 적은 배까지 와서 멈춘다(배 무적) — 같은 조건이라 계열끼리 비교는 공정하다.
   적 종류는 해역 1의 첫 적(기본 `crab`, `--wave-kind`로 변경). 공중·물속 제외 계열이 손해 보지 않게 물위 적.
5. **(B) 보스전**: `OpSpawnBoss` 하나, 보스 제한 시간(`waves.json boss.timeLimitSec`, 지금 30초) 동안의 피해 × (60 ÷ 제한 시간)로 60초 환산.
6. **점수**: 선원 점수 = (A + B) / 2. 비교는 같은 레벨의 40명 **중앙값 대비 비율**(1.00 = 중앙값).
7. **지원 환산**(충격 계열 + 배 스킬 선원 `support_rally` 등 `shape: ship`): 기준 파트너(같은 레벨의 직사 계열 첫 선원, `--partner`) 하나와 함께 둘이서 A·B를 재고
   - 파트너 증가분 = 파트너 피해(함께) − 파트너 피해(혼자)
   - 배 보호분 = κ × (배에 닿은 적·틱(파트너 혼자) − 배에 닿은 적·틱(함께)) — κ는 "배에 적 1마리가 1초 붙어 있는 것"을 피해 몇으로 칠지(기본: 같은 레벨 중앙 선원 A의 초당 피해 × 0.5, `--kappa`)
   - 지원 선원 점수 = 자기 피해 + 파트너 증가분 + 배 보호분.
   "배에 닿은 적·틱"은 무적이면 `ShipDamaged`가 나오지 않으므로 아래 열린 질문 Q1로 정한다.
8. **판정 1**: 어느 칸이든 중앙값의 ±10% 밖이면 실패(표에 ✗).
9. **판정 2 — 조합**: 레벨 45(대표)에서 6명 조합을 시드 고정 무작위 `N`(기본 500)개 — 자동 편성 규칙대로 **같은 계열 최대 2명** — 뽑아 6명 함대로 A·B를 재고,
   조합 점수 상위 1%가 조합 점수 중앙값 × 1.3을 넘으면 실패. 상위 조합 5개를 표에 남긴다.
10. **출력**: 마크다운(레벨별 표: 선원·계열·A·B·점수·비율·판정, 끝에 조합 요약) 표준 출력 + `--out <json>`(같은 내용). 종료 코드 0 통과 / 1 위반 / 2 측정 오류.
11. **옵션**: `--levels 15,30`(부분), `--crews octo,pang`, `--combos N`, `--seed`, `--quick`(레벨 45만·조합 50 — check용).
12. **성능 목표**: 전체(200칸 + 지원 환산 + 조합 500) 로컬 3분 이내. 넘으면 조합 N 기본값을 낮춘다.

## 수용 기준 — `packages/game_cli/test/balance/`
1. Given 같은 시드 When 두 번 실행 Then JSON이 바이트까지 같다.
2. Given 선원 1명·레벨 45 When A 측정 Then 60초(1200틱)의 `Damage` 합 = 리포트 A 값, 측정 중 `Kill` 없음.
3. Given S_tank와 S_tank+300(한 바퀴 뒤, 역시 일반 보스) When 같은 선원 측정 Then A·B 피해량이 같다(스테이지 무관 가정 확인).
4. Given B When 보스 제한 시간 30초 Then 리포트 B = 30초 피해 × 2.
5. Given 가짜 테이블(한 선원 배율을 ×1.2) When 실행 Then 그 선원 칸 ✗, 종료 코드 1. 원래 테이블 수치로 통과 여부는 S1 판단(표만 정확하게).
6. Given 조합 샘플 When 뽑기 Then 모든 조합이 같은 계열 2명 이하, 시드 고정이면 같은 조합 목록.
7. Given 충격 선원 When 지원 환산 Then 점수 = 자기 피해 + 파트너 증가분 + 배 보호분(각 항목이 JSON에 따로 남는다).
