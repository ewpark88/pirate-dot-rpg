# 실기기 상시 확인 규칙 (Device Loop)

> 사용자 2026-10-17: "연결된 기기에 개발한 걸 계속 적용해서 바로바로 확인하고, 게임을 플레이하면서 문제나 UI 수정할 부분을 끊임없이 찾아라."
> 폰(S24, `R3CX90JQLEB`)과 태블릿(Galaxy Tab S7 FE, 2026-10-17 연결)은 늘 USB로 연결돼 있다고 본다. 사용자 2026-10-17: "연결된 태블릿에서 개발된 것을 지속적으로 테스트해라 — 너(S1)가 확인하면서 테스트하고 수정하는 거다." 담당: **S1이 설치·확인을 직접**(S5 세션은 adb 설치·입력 권한이 막혀 있음), 찾은 문제는 S1이 레인에 배정한다. 태블릿에서는 크기(레이아웃 넘침·여백·글자 크기)를 매번 같이 본다.

## 1. 언제 돌리나 (끊임없이)
| 시점 | 할 일 |
| --- | --- |
| main에 화면·연출·밸런스 변경이 머지되고 빠른 check가 초록일 때(최대 30~40분마다 한 번) | 운영자 release apk 빌드(A줄) → 설치 → `release_smoke.py` → 플레이 확인(3절) |
| 설치 사이사이 | 지금 설치본으로 플레이 확인을 다른 구간(해역·피버·보스·창)으로 반복 |
| 사용자가 "폰에 설치해줘"라고 하면 | 다른 일보다 먼저 S1이 빌드·설치 |

## 2. 안전 규칙 (어기면 즉시 멈춤)
- **누르기·키 입력 직전마다 우리 앱(`repo.dot.pirate`)이 맨 앞인지 확인**한다. 아니면 아무것도 보내지 않고 기다린다(사용자가 폰을 쓰는 중). 2026-10-15에 앱이 뒤에 있는데 눌러 전화 앱을 연 사고가 있었다.
- 보내는 입력은 **우리 앱 화면 누르기(input tap)·끌기(swipe)·뒤로 키**뿐. 잠금 해제·비밀번호·문자 입력·알림창·다른 앱은 절대 건드리지 않는다.
- 앱 데이터(세이브) 지우기·제거 금지(사용자 세이브). 새 게임이 필요하면 **운영자 패널**의 기능만 쓴다.
- 실제 결제·실광고 금지(테스트 광고 ID만). 광고 화면이 뜨면 닫기만.
- 다른 앱 화면이 캡처에 찍히면 **그 파일을 바로 지운다**(개인 정보). 기록·보고에 다른 앱 내용을 쓰지 않는다.
- 설치는 앱을 다시 시작시키므로, 앱이 맨 앞이고 1분 넘게 입력이 없을 때(사용자가 플레이 중이 아닐 때) 한다.

## 3. 플레이 확인 (한 번에 10~15분)
1. 시작 화면 → 전투 2분(초반 무리·콤보·카드 연출·체력 숫자)
2. 아래 탭 5개 + 대표 창(배 강화·모두 강화·선원 상세·교체 비교·소환·도감·설정·퀘스트)
3. 운영자 '오늘 새 기능'으로 피버·보스 브레이크·특성 보스·연쇄 번개·출항 대기를 불러 확인
4. 각 단계 화면 캡처 → `build/device/loop/<시각>/`, `logcat -b crash`, SurfaceFlinger 프레임·온도(thermal_log)

## 4. 찾는 것 (캡처마다 체크)
- 넘침·잘림·겹침·글자 안 읽힘(4.0:1 미만)·버튼 48dp 미만·화면 밖 그림
- 연출이 안 보임·너무 작음·너무 많음·끊김(프레임 p95 > 25ms)·소리 안 남
- 쿵푸할매 기준과 어긋남(외곽선·리본·입체 버튼·HD 그림 섞임 도트)
- 밸런스 체감(보스가 너무 빨리/늦게 죽음, 배가 안 닳음, 골드 금고 너무 빨리 참)
- 크래시·멈춤·느린 시작

## 5. 보고·처리
- 찾은 문제는 S1에 표 한 장(캡처 경로·어디서·무엇이·누구 몫 제안). S1이 바로 레인에 배정하고 `docs/plans/active/user-feedback-*.md`에 '기기 확인' 출처로 적는다.
- 사용자에게는 S1이 묶어서 짧게 보고한다.
