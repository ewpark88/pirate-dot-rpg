# 실기기 확인 (M2 관문)

설계서 11장: **M2 관문에서 손맛이 없으면 M3로 가지 않고 연출·속도를 다듬는다. 손맛은 시뮬로 검증할 수 없는 유일한 항목이다.**
이 문서대로 기기에서 두 가지(손맛, 성능)를 보고 결과를 S1에게 알려 준다.

> **탑다운 기준 실기기 확인 목록(15분)은 [docs/plans/active/platform-device-check-topdown.md](plans/active/platform-device-check-topdown.md)를 먼저 본다.** 아래 1절의 옆모습 문구는 옛 내용이다.

## 0. 준비 (처음 한 번)
- **release는 반드시 `python -I -B docs/store/device/release_smoke.py` 통과 후 사람에게 넘긴다**(2026-10-15 release 실행 즉시 종료 사고 — 빌드 검사로는 실행 중 크래시를 못 잡는다).
- Android 폰(가능하면 저사양 1대), 설정 → 개발자 옵션 → USB 디버깅 켬, PC와 USB 연결
- PC에서:
```bat
cd /d D:\Projects\pirate-dot-rpg\apps\game
flutter devices
```
  목록에 폰이 보이면 그 id(예: `R5CT...`)를 아래 `<기기id>`에 넣는다.

## 1. 손맛 확인 — 실제 게임 (약 10분)
```bat
flutter run --profile -d <기기id> --dart-define=OPERATOR=true --dart-define=PERF_OVERLAY=true
```
- `BATTLE_SCENE`을 안 주면 전장은 **실제 엔진 전투(live)**, `PERF_OVERLAY=true`면 live에서도 왼쪽 위 fps·p95 숫자와 터미널 `[perf]` 요약이 나온다.

새 게임으로 시작한다(옥토·톡). 아무것도 누르지 않고 1분 지켜본 뒤, 아래를 차례로 해 본다.

| # | 볼 것 | 기대 |
| --- | --- | --- |
| 1 | 무리가 오른쪽에서 몰려오고 배가 알아서 쏜다 | 범위 폭발에 여러 마리가 함께 터진다. 숫자·번쩍임·짧은 멈춤(히트스톱)이 느껴진다 |
| 2 | 약 1분 뒤 첫 보스 | 30초 안에 못 잡으면 '파밍 중'으로 바뀐다 |
| 3 | 배 탭에서 대포·선체 강화 몇 번 → 보스 도전 버튼 | 다시 도전해서 잡힌다(강화 → 보스 루프가 자연스러운가) |
| 4 | 첫 보스를 잡은 뒤 소환 탭 | 첫 10연이 무료, 영웅 이상 1장 |
| 5 | 함성 게이지가 차면 | 궁극기가 화면 전체로 터진다(자동) |
| 6 | HUD 톱니 → 설정 | 흔들림·번쩍임·진동 끄기가 바로 반영된다 |
| 7 | 홈 버튼으로 나갔다가 1분 뒤 복귀 | 오프라인 보상 팝업이 1개 뜬다 |
| 8 | 앱을 완전히 종료 → 다시 실행 | 스테이지·골드·선원이 그대로다(저장·복원) |
| 9 | (운영자) HUD의 스테이지 글자 5번 탭 → 패널 | 스테이지 50·100으로 이동 → 보스 소환 → 해역 보스(보호막·촉수 등)를 본다 |

**알려 줄 것**: 손맛 OK / 다듬기 필요. 다듬기 필요면 무엇이(예: "타격이 가볍다", "보스가 너무 오래 걸린다", "숫자가 너무 많다") — 느낌 그대로 적어도 된다.

## 2. 성능 확인 — 부하 장면 (약 2분)
```bat
flutter run --profile -d <기기id> --dart-define=OPERATOR=true --dart-define=BATTLE_SCENE=stress --dart-define=PERF_OVERLAY=true
```
1. 전장에 부하 장면(적 24마리 이상, 0.5초마다 범위 폭발)이 반복된다. 아무것도 누르지 않고 60초 기다린다.
2. PC 터미널에 10초마다 찍히는 `[perf] fps=… p50=… p95=… max=… slow=…` 줄의 **마지막 6줄**을 복사한다.
3. 합격 기준: p95 ≤ 16.7ms, max ≤ 33ms가 1초에 1번 이하 (docs/specs/render-perf.md).

**알려 줄 것**: 기기 이름·Android 버전 + 6줄.

## 3. 플랫폼 확인 — 광고·알림·저장·이름 (약 15분)
```bat
flutter run --profile -d <기기id> --dart-define=OPERATOR=true
```
- `google-services.json`이 없으면 분석은 꺼진 채로 돈다(정상). 광고는 **테스트 광고**("Test Ad" 표시)만 나온다 — 실제 광고를 누르지 않는다.
- 터미널 로그에서 `ads:`·`notify:`·`analytics:`·`audio:`·`save:`로 시작하는 줄이 실패 이유다. 문제가 있으면 그 줄을 함께 보낸다.

| # | 할 것 | 기대 | 대신 (운영자 버튼 전) |
| --- | --- | --- | --- |
| 1 | 앱을 처음 실행 | 한국이면 동의 창 없이 시작(UMP는 EU·영국 등에서만 뜸). 멈추거나 튕기지 않는다 | — |
| 2 | 30초쯤 기다린 뒤 홈의 순풍 광고 버튼 | 버튼이 보이고, 누르면 테스트 광고 → 끝까지 보면 '30분 ×2'가 붙는다. 중간에 닫으면 보상 없음 | — |
| 3 | 광고를 본 직후 다른 광고 버튼(소환 탭 무료 소환) | 몇 초 안에 다시 준비된다. 비행기 모드면 버튼이 **숨는다**(누를 수 없는 버튼이 보이면 안 됨) | — |
| 4 | 운영자 패널 → "알림 10초 뒤" → 바로 홈 버튼 | 처음이면 알림 권한 창(Android 13+), 허용 → 10초쯤 뒤 알림 1개(제목·문구 한국어). 누르면 앱이 열린다 | 홈으로 나가서 8시간 기다림(실용적이지 않음 — 버튼 반영 뒤 확인) |
| 5 | 홈 버튼으로 나갔다 1분 뒤 복귀 → 다시 나가기 | 1분 이상 비운 첫 복귀에 권한을 1번만 묻는다(4에서 이미 물었으면 안 물음). 복귀하면 예약된 알림이 취소된다 | — |
| 6 | 기기 언어를 영어로 바꾸고 런처 보기 | 앱 이름 한국어 `해적도트 원정대` / 영어 `Pirate Dot`(영문 이름 확정 전 임시) | — |
| 7 | 1분 플레이 → 최근 앱에서 밀어서 강제 종료 → 재실행 | 스테이지·골드·선원이 그대로(백그라운드 저장). 10초 자동 저장도 있어서 1분 안 잃는다 | — |
| 8 | 설정(톱니) | 한국에선 '개인정보 옵션'이 **안 보이는 게 정상**(EU에서만) | — |
| 9 | 소리 | 지금은 효과음 파일이 없어 **무음이 정상**. 튕기지 않으면 OK | — |

**알려 줄 것**: 기기 이름·Android 버전, 1~9 각각 OK / 이상(이상이면 무엇이 + 위 접두어 로그 줄).

### 결과를 받으면 (S1 → platform)
- 광고(2·3)·알림(4·5)·저장(7) 이상 → platform 레인에 로그 줄과 함께. SDK 연결 파일(`google_ads_sdk`·`local_notifications_sdk`·`firebase_sdk`·`flame_audio_sdk`)은 단위 테스트가 없어 여기가 유일한 확인이다.
- 6 이름 → 영문 이름 확정되면 `res/values/strings.xml`만 바꾼다.

## 결과를 받으면 (S1)
- 손맛 OK + 성능 합격 → PROGRESS.md M2 체크, M3 본격 진행.
- 손맛 다듬기 → 연출·속도 수치(juice.json, waves.json, skills.json)를 조정해 다시 이 문서로.
- 성능 불합격 → render 레인에 `slow` 구간 값과 함께 넘긴다.
