## 단계별 작업

### 1. 뼈대
- `git init`, `.gitignore`(Flutter/Dart 표준 + `apps/game/lib/l10n/merged/`).
- 루트 `pubspec.yaml`: `workspace:` 에 game_data, game_core, game_cli, apps/game, tool. SDK `^3.12.0`.
- `flutter create --org repo.dot --project-name pirate_dot --platforms android,ios apps/game` 후 applicationId / iOS bundle id를 `repo.dot.pirate`로 수정, `resolution: workspace` 추가.
- 앱 의존성: flame(1.38.x), flutter_riverpod, flutter_localizations, intl. AdMob·Firebase·path_provider는 플랫폼 레인(M4)으로 미룸.
- 설계서 원본을 `docs/GAME_DESIGN.md`로 이동(루트 사본 제거해 이중화 방지).

### 2. game_data (의존: dart:core, dart:convert만)
- `tables/` 11개 JSON을 설계서 4~5장 수치로 채움: crews, growth, rarities, ship_parts, ship_tiers, skills, waves, regions, juice, fx_map, ads, meta.
- `crews.json`은 `tool/import_crews.dart`로 `characters.json`에서 생성(l10n 키 `crew.<id>.name` 등). 이름 문구는 `apps/game/lib/l10n/parts/crew.{ko,en}.arb`로.
- dart:io를 못 쓰므로 `tool/gen_tables.dart`가 JSON을 `lib/src/tables.g.dart`(const 문자열)로 임베드. check가 최신 여부 비교 → 실패 메시지 “`dart run tool/gen_tables.dart` 실행”.
- 모델 클래스 + `validateTables()`: 확률 합 1.0, 증가율 > 1, 등급별 인원(12/12/8/8), 계열별 5명, 참조 id 존재. 테스트로 상시 검증.

### 3. game_core 계약 (0단계 고정 대상)
- `lib/contracts.dart` (export 전용 공개 API):
  - `GameState`(불변 스냅샷: wallet, progress, ship, crews, buffs, daily, settings, battle view) — 세이브 스키마 v1(설계서 5.2)과 1:1.
  - `sealed class Command`: UpgradePart, Summon, MergeAllCards, PromoteCrew, ChallengeBoss, TriggerUltimate, GrantAdReward(AdPlacement), Rebirth, ExchangeToken, SetSetting, `OperatorCommand`(sealed 하위: SetCrew, GrantCurrency, JumpStage, SetSpeed, ForceBoss, ToggleInvincible, AdvanceClock, LoadState …).
  - `sealed class GameEvent`: Damage, Kill, MultiKill, CritHit, SkillCast, UltimateCast, BossSpawned, BossCleared, BossFailed, HitStop(ticks), StageAdvanced, ShipTierUp, PartMilestone, CrewPromoted, BestStageUpdated, OfflineReward.
  - 포트: Clock, Rng, SaveStore, AdsPort, AnalyticsPort, LeaderboardPort(설계서 8.1 시그니처), PurchasePort.
  - `GameEngine` 인터페이스: `tick()`(50ms 고정), `enqueue(Command)`, `state`, `drainEvents()`.
- 계약이 의존하므로 `BigNum`(가수 double + 지수 int, 정규화·사칙·pow·비교·`"1.25e6"` 직렬화·K/M/B/T/aa 포맷)을 이번에 구현 + 속성 테스트.
- 세이브 v1 코덱: JSON ↔ GameState, 체크섬(sha256, `crypto` 허용 → ADR), 마이그레이션 체인 틀(`migrations = []`). `test/fixtures/saves/v1_sample.json` + 왕복 테스트.
- 테스트용 포트 구현(ManualClock, XorShiftRng, MemorySaveStore, InstantAds, RecordingAnalytics, MemoryLeaderboard)은 `lib/testing.dart`로 공개.
- 엔진 스텁: 명령을 다음 틱에 적용하는 큐 + 이벤트 버퍼만. 실제 규칙은 battle/economy 레인 몫.

### 4. 픽스처·CLI
- `fixtures/states/`: new_player, stage37_midgame, boss_fight, all_crews_mythic (UI 레인 입력). 로드 테스트로 계약과 일치 보장.
- `fixtures/events/sample_battle.jsonl`: GameEvent JSON 직렬화 형식으로 손으로 쓴 샘플(렌더 레인 입력). 이후 `export-events`가 대체.
- `scenarios/`: 설계서 7.1 형식 YAML 1개(boss_fail) — 러너 틀만, 현재는 `skip: M1`.
- game_cli: `args` 기반. `save inspect`는 동작(검증·마이그레이션 출력). sim/replay/export-events/balance는 “담당 레인·마일스톤” 안내 후 exit 2.

### 5. 하네스 (전부 Dart, `tool/`)
각 검사는 `root` 경로를 받는 함수로 작성해 임시 폴더로 자체 테스트 가능. 실패 메시지는 “무엇을 어디로 옮겨라” 형식(설계서 6.3).
- `check_deps.dart`: 모든 `lib/` import를 3.1 허용 표와 비교, 앱의 `lib/src/` 침범, `render/`→명령 발행, `adapters/`→ui/render import 금지.
- `check_rules.dart`: game_core의 `DateTime.now`/`Random(`/`Stopwatch`; `battle/`·`economy/`의 0·1 외 숫자 리터럴; apps/game/lib의 `Text('…')`·한글 리터럴(l10n 생성물 제외); 300줄 초과 파일(생성물 제외); `assets/LICENSES.json` 미등록·비허용 라이선스; 운영자 코드가 `lib/operator/` 밖에서 `kOperator` 가드 없이 참조되는지.
- `merge_arb.dart`: `parts/*.{ko,en}.arb` → `l10n/merged/app_{ko,en}.arb`, ko/en 키 불일치·접두어 충돌 시 실패. `l10n.yaml`이 merged를 읽음.
- `check_lane.dart`: 현재 브랜치가 `lane/<이름>`(·`lane/<이름>/*`)이면 `git diff main...HEAD` 변경 파일이 LANES.yaml 소유 경로 + 자기 `docs/plans/`·`docs/contracts/requests/` 밖이면 실패. `main`은 통과.
- `check.dart` 순서(첫 실패에서 중단): format → analyze(`--fatal-infos`) → deps/rules/arb/tables 최신성 → lane → `dart test`(game_data, game_core, game_cli, tool) → 시나리오 → 밸런스 스모크(M1 전까지 skip 표시) → `--full`일 때 `flutter test`(apps/game).
- `check.bat` / `check.sh`: `dart run tool/check.dart %*`.
- 자체 테스트 `tool/test/`: 일부러 규칙 위반 파일(코어에 flutter import, DateTime.now, ko만 있는 ARB, 301줄 파일, 레인 밖 수정)을 임시 트리에 만들고 각 검사가 실패하는지 확인 → M0 DoD “어긴 코드가 실패하는지 확인”.

### 6. Claude Code 훅·명령
- `.claude/settings.json`:
  - PostToolUse(Edit|Write) → `dart run tool/hooks/post_edit.dart`: 수정한 .dart 파일 format + 해당 패키지 analyze, 문제는 stderr로 돌려줌.
  - PreToolUse(Edit|Write) → `tool/hooks/pre_edit.dart`: `test/fixtures/saves/`, `**/goldens/` 수정 시 exit 2 + “갱신은 사람이 명령으로만”.
  - Stop → `tool/hooks/stop_check.dart`: `stop_hook_active`면 통과, 아니면 빠른 check 실행, 실패 시 exit 2로 종료 차단. 추가로 코드 변경이 있는데 `docs/PROGRESS.md`가 갱신되지 않았으면 차단(“진척 문서를 갱신하세요”).
- `.claude/commands/lane-start.md`: 인자 레인 → AGENTS.md, `docs/PROGRESS.md`, `docs/lanes/<레인>.md`, LANES.yaml의 소유 경로, `docs/plans/active/<레인>-*.md`를 읽고 오늘 할 일 요약.

## 검증
1. `tool\check.bat` 녹색, `tool\check.bat --full` 녹색(flutter test 포함).
2. `dart test tool/` — 의도적 위반 케이스가 모두 실패로 잡힘.
3. 수동 위반: game_core에 `import 'package:flutter/...'` 임시 추가 → check 실패 메시지 확인 후 원복.
4. 훅: 각 hook 스크립트에 샘플 JSON을 stdin으로 넣어 exit code 확인(pre_edit가 fixtures/saves 경로에 2 반환 등).
5. `dart run game_cli save inspect test/fixtures/saves/v1_sample.json` 정상 출력.
6. `flutter build apk --debug` (apps/game) 성공 — 패키지 ID `repo.dot.pirate` 확인.
