# 해적도트 원정대 개발 설계서

Oct 6, 2026 · @ewpark

## 1. 개요

해적도트 원정대는 바다를 항해하며 몬스터 무리를 범위 공격으로 쓸어버리는 도트 방치형 RPG다. Pirate Busters의 방치형 외전으로, 그 해적 40명을 도트로 다시 그려 선원으로 쓰고, Flutter + Flame 한 코드베이스로 Android와 iOS에 낸다. 게임 규칙은 순수 Dart 패키지에 모아, 여러 Claude Code 세션이 모듈을 나눠 병렬로 개발한다(6.8절).

**목표**

- 조작은 ‘배 강화’와 ‘선원 소환’ 두 개로 단순하게, 화면은 핵앤슬래시처럼 화려하게.
- 배가 눈에 보이게 자라고, 시간·일·주 단위 목표가 계속 이어져 오래 키우게 한다.
- 1차 출시는 오프라인 싱글플레이, 무료 + 보상형 광고. 2차에 랭킹을 붙이며, 1차 코드는 어댑터만 추가하면 되게 설계한다.
- 모든 기능은 처음부터 한국어·영어를 함께 만든다. 영어가 빠진 기능은 완료가 아니다.

**슬로건: 재미있게, 시원하게, 단순하게. 피로는 주지 않는다.**

모든 기능은 스펙 단계에서 아래 4가지를 통과해야 넣는다. 하나라도 걸리면 고치거나 뺀다.

1. **시원한가**: 화면에서 터지는 순간이나 숫자가 크게 뛰는 순간을 만드는가.
2. **단순한가**: 새 버튼·새 재화·새 화면이 생기는가. 생긴다면 기존 것을 하나 없애거나 합칠 수 있는가.
3. **피로가 없는가**: 플레이어가 매일 의무적으로 눌러야 하는 것이 늘어나는가. 놓쳤을 때 손해를 보게 만드는가(둘 다 금지).
4. **공정한가**: 어떤 선원 하나가 다른 선원을 쓸모없게 만드는가(4.8절 검사를 통과해야 함).

**제약**

| 항목 | 결정 |
| --- | --- |
| 비용 | 개발·운영비 0원. 무료 도구, 무료 티어, 무료 에셋만 사용 |
| 플랫폼 | Android 우선 출시, iOS는 같은 코드로 뒤따라 출시 |
| 언어 | 한국어·영어 동시 지원, OS 언어에 따라 자동 전환 |
| 서버 | 1차는 서버 없음(로컬 저장). 2차 랭킹만 서버리스 무료 티어 |
| 개발 방식 | 하네스 엔지니어링: 코드는 에이전트가 쓰고, 사람은 규칙·검증 장치·배포를 관리 |

**범위 밖 (1차)**

- 인앱결제(IAP). 젬은 보스 보상과 광고로만 얻는다. 단, 결제 포트 자리는 남겨둔다.
- 클라우드 세이브, 계정, 친구, 채팅, 실시간 PvP.
- 서버 이벤트, 원격 밸런스 조정(데이터 테이블은 앱에 포함).

## 3. 아키텍처

게임 규칙은 전부 `game_core`에 있고, 앱은 그 상태를 그리고 입력을 명령으로 바꿔 넘기기만 한다. 외부 세계(시계, 난수, 파일, 광고, 서버)는 포트 인터페이스로만 만나므로, 테스트는 가짜 구현을, 앱은 진짜 구현을 끼운다.

&#91;embedded content: 패키지 구조 · 화살표 = 의존 방향\]

화살표 방향으로만 import할 수 있고, 거꾸로 가는 import는 `check_deps.dart`가 막는다. 점선은 어댑터가 코어의 포트를 구현한다는 뜻이다.

### 3.1 의존 규칙

| 패키지 | import 허용 | import 금지 |
| --- | --- | --- |
| `game_data` | `dart:core`, `dart:convert` | 나머지 전부 |
| `game_core` | `game_data`, `meta`, `collection` | Flutter, `dart:io`, `dart:ui`, Flame, 모든 플러그인 |
| `game_cli` | `game_core`, `game_data`, `dart:io`, `args` | Flutter |
| `apps/game` | 위 패키지의 공개 API(`lib/*.dart`) | 다른 패키지의 `lib/src/` |

앱 내부는 `render/`, `ui/`, `adapters/` 세 폴더로 나눈다. `render/`는 상태를 읽기만 하고 명령을 내지 않으며, `adapters/`는 화면 코드를 import하지 않는다.

### 3.2 포트

| 포트 | 1차 구현 | 테스트 구현 | 2차 |
| --- | --- | --- | --- |
| `Clock` | 시스템 시계 | 수동으로 돌리는 시계 | 서버 시간 보정 |
| `Rng` | 시드 고정 PRNG(xorshift) | 같은 구현, 시드 지정 | - |
| `SaveStore` | JSON 파일 | 메모리 | 클라우드 백업 추가 가능 |
| `AdsPort` | AdMob 보상형 | 즉시 보상 | - |
| `AnalyticsPort` | Firebase Analytics | 이벤트 기록기 | - |
| `LeaderboardPort` | 아무것도 안 함 | 메모리 | Cloudflare Workers |
| `PurchasePort` | 없음 | - | IAP 도입 시 |

### 3.3 결정론적 시뮬레이션

- 코어는 `GameEngine.tick()`을 50ms마다 한 번 돌린다. 화면 프레임(60fps)과 무관하며, 렌더는 두 틱 사이를 보간해 그린다.
- 입력은 `Command`(강화 구매, 소환, 보스 도전, 광고 보상 지급)로만 들어오고 다음 틱에 적용된다.
- 코어는 상태와 `GameEvent`(피해, 처치, 보스 클리어)를 내보낸다. 효과음·데미지 숫자·파티클은 이벤트를 보고 렌더가 만든다.
- 배속 실행이 가능하므로 밸런스 시뮬은 게임 시간 8시간을 수 초에 돌린다.

## 4. 게임 시스템 (바다판)

플레이어가 누르는 버튼은 ‘배 강화’와 ‘선원 소환’ 두 개다. 전투·스킬·배 승급은 전부 자동이고(출전은 직접 고르거나 ‘자동 편성’ 버튼 한 번), 화려한 범위 공격과 눈에 보이게 커지는 배가 보상이다. 모든 시스템은 `game_core`에서 20Hz 고정 틱과 시드 고정 난수로 돌고, 수치는 데이터 테이블(5장)에서 읽는다.

### 4.1 코어 루프

1. 해적선이 항해하며 다가오는 바다 몬스터 무리를 배가 자동으로 잡는다. 배에 탄 선원마다 자기 계열의 발사체를 쏜다.
2. 처치하면 골드가 튀어나온다. 골드로 배 부위를 강화한다.
3. 스테이지마다 무리 3파를 잡으면 보스(적 해적선, 바다 괴물)가 나온다. 30초 안에 잡으면 다음 스테이지 + 젬.
4. 못 잡으면 제자리 항해(파밍)로 돌아가 골드를 모으고, 플레이어가 ‘보스 도전’을 누른다.
5. 젬으로 선원을 소환한다. 강한 선원이 자동으로 배의 무기 슬롯에 탄다.
6. 앱을 꺼도 최대 8시간분 골드가 쌓인다.

### 4.2 배 강화 (골드)

프로토타입의 능력치 5종을 배 부위 5종으로 바꾼다. 수치 의미는 같고, 화면에서 배가 변한다.

| 부위 | 효과 | 수식 | 비용 | 보이는 변화 |
| --- | --- | --- | --- | --- |
| 대포 | 선원 전체 공격력 | `4 × 1.3676^Lv` | `10 × 1.5209^Lv` | 포신 크기·개수 증가 |
| 선체 | 배 HP | `550 × 1.4049^Lv` | `10 × 1.5209^Lv` | 나무 → 철판 → 금장식 |
| 돛 | 공격 속도·스킬 쿨타임 | `1 + 0.05 × Lv` (최대 30) | `60 × 2.0972^Lv` | 돛 크기·문장 |
| 망루 | 치명타 확률 | `5% + 1% × Lv` (최대 45) | `50 × 2.0972^Lv` | 돛대 위 망루·망원경 |
| 화물칸 | 골드 획득 | `1 + 0.3 × Lv` | `40 × 1.728^Lv` | 갑판 위 보물상자 |

- **강화는 드물고 크게** (사용자 지시 2026-10-16 '골드가 아쉽지 않다'): 예전 곡선(성장·비용)의 세제곱 — 한 번 누르면 예전 3레벨만큼. 스테이지 10 무렵 강화 간격 약 15초.
- **갈수록 드물게** (가속, S1 승인 2026-10-16): 대포·선체·화물칸은 Lv 8부터 공식의 레벨 자리가 `Lv + (Lv − 8)² ÷ 8`(accelFrom 8·accelLevels 4) — 한 번이 더 크고 비싸져 스테이지 40 무렵 강화 간격 약 50초. 옛 세이브는 v7에서 그 세 부위 레벨 ÷3(ADR-0011).
- **마일스톤 도약**: 대포·선체·화물칸은 8레벨마다 효과 ×2 + 외형 변화 + 빛기둥 연출. 숫자가 크게 뛰는 순간을 주기적으로 만든다.
- **배 승급 (자동)**: 스테이지 도달 시 배가 바뀜다. 플레이어가 고를 것은 없다.

| 배 등급 | 승급 스테이지 | 무기 슬롯 수 | 추가 효과 |
| --- | --- | --- | --- |
| 쪽배 | 1 | 3 | - |
| 범선 | 30 | 4 | 전체 피해 +20% |
| 해적 군함 | 80 | 5 | 전체 피해 +50% |
| 유령선 | 150 | 6 | 전체 피해 +100% |

### 4.3 선원 (젬 소환)

Pirate Busters의 40명을 도트로 다시 그려 쓴다(10장). 희귀도는 일반 12 · 희귀 12 · 영웅 8 · 전설 8명이고, 계열 8개에 5명씩이다.

- 소환은 ‘해적 카드’를 준다. 카드 등급 확률: 일반 65%, 희귀 27%, 영웅 7%, 전설 1% (신화는 소환에 없음). 50회 안에 영웅 이상 확정.
- 등급은 Pirate Busters와 같은 5단계(일반·희귀·영웅·전설·신화)이고, 카드 프레임과 별 수도 PB 10.5절을 그대로 따른다. 단, 이 게임에서는 등급이 해적마다 고정이 아니라 카드를 합쳐 올린다(4.3.1).
- 출전은 무기 슬롯 수만큼 플레이어가 고른다(수동 편성, ADR-0010). ‘자동 편성’ 버튼은 파워 상위부터 한 번에 채운다. 배 등급이 올라 슬롯이 늘면 빈 칸으로 두고 배지로 알린다. 전장에는 선원이 보이지 않고, 화면 아래 슬롯에 초상과 쿨타임만 보인다.
- 가장 등급이 높은 출전 선원이 ‘선장’이 되고, 선장의 궁극기가 4.4의 함성 게이지로 발동한다.

#### 4.3.1 성장: 카드 합치기와 승급

레벨은 하나로 이어지고(Lv1\~75), 15레벨마다 승급 문을 둔다. 등급은 레벨 구간이다.

| 등급 | 레벨 구간 | 얻는 법 | 다음 등급 승급 조건 | 승급 시 발사체 변화 |
| --- | --- | --- | --- | --- |
| 일반 ★ | Lv1\~15 | 소환 65% | Lv15 + 같은 해적 카드 3장 + 골드 (4.3.3) | 푸른 꼬리, 발수·연쇄·범위 +1단계 |
| 희귀 ★★ | Lv16\~30 | 소환 27% | Lv30 + 카드 6장 + 골드 | 보라 리본, +1단계 |
| 영웅 ★★★ | Lv31\~45 | 소환 7% | Lv45 + 카드 10장 + 골드 | 금 리본·별, 명중 시 화면 금빛, +1단계 |
| 전설 ★★★★ | Lv46\~60 | 소환 1% | Lv60 + 카드 20장 + 증표 50 + 골드 | 스킬 범위가 화면 전체로 커짐 |
| 신화 ★★★★★ | Lv61\~75 | 승급으로만 (소환에 없음) | 끝 | 프리즘 꼬리·무지개 명중(PB 10.5 신화 연출), 위력은 전설과 같은 배율 규칙 |

신화는 운이 아니라 노력으로만 갈 수 있게 소환에서 뺀다. 소환 운에 따른 격차가 가장 크게 벌어지는 지점을 막기 위해서다.

- **레벨업 = 카드 합치기**: 같은 해적의 카드를 합치면 경험치가 오른다. 카드 등급이 높을수록 경험치가 크다(일반 1, 희귀 4, 영웅 15, 전설 60). 골드는 승급에만 쓴다.
- **더 높은 등급 카드**: 아직 해당 등급에 못 간 해적의 높은 등급 카드를 뽑으면, 승급 조건 없이 그 등급의 첫 레벨로 뛰어오른다. 전설 카드를 뽑는 순간의 쾌감을 지킨다.
- **위력**: `선원 파워 = 기본 × (1 + 0.08 × (Lv - 1)) × 1.35^(승급 횟수)`. 같은 레벨이면 등급이 높을수록 항상 강하다(PB 규칙과 같음).
- **승급은 전장에서 보인다**: 선원은 전장에 없으므로, 승급하면 그 선원의 발사체가 눈에 띄게 바뀐다. 꼬리·명중 연출은 PB 10.5절의 ‘전투 등급 연출’ 표를 그대로 쓰고, 계열별로 한 단계씩 강해진다(투척 폭발 반경, 직사 연사 수, 관통 작살 수, 물수제비 연쇄 수, 공중 타격 수 등).
- **보유 효과**: 출전하지 않은 선원도 레벨만큼 배 전체 공격력을 조금씩 올린다(선원 하나당 Lv × 0.1%). 40명 모두 키울 이유가 생긴다.
- **남는 카드**: 어느 등급이든 다음 승급에 필요한 장수를 넘는 카드(신화 Lv75는 모든 카드)는 ‘해적의 증표’로 바뀌고, 증표는 상점에서 원하는 해적의 카드로 교환한다. 쓸모없는 카드가 없게 한다. (2026-10-14 결정: 신화가 없으면 증표가 생기지 않아 첫 신화에 도달할 수 없던 문제)

**방치형을 지키는 장치**

- **일괄 합치기 버튼 하나**: 모든 해적의 합칠 수 있는 카드를 한 번에 합친다. 승급은 연출을 보여주려고 해적별 버튼으로 둔다(승급 가능하면 빨간 점).
- **카드가 계속 들어오는 길**: 소환 외에 보스 처치(카드 1장), 오프라인 보상(8시간 기준 3장), 떠내려오는 보물상자, 일일 퀘스트. 앱을 켜면 항상 합칠 카드가 있는 상태를 만든다.
- **전투는 그대로 자동**: 합치기·승급·편성은 전투 밖에서 하는 일이다. 편성은 한 번 정해 두면(또는 ‘자동 편성’ 한 번) 방치 중에는 아무것도 고를 필요가 없다.
- **목표 속도**: 첫 승급(Lv15)은 플레이 30분 안쪽, 첫 영웅 승급은 3일 안쪽, 첫 전설 승급은 2\~3주. 밸런스 시뮬(7.2절)에 목표를 추가한다.

#### 4.3.2 등급별 발사체 사다리

승급하면 발사체가 ‘한 단계’ 늘어난다. 수가 늘어도 총 예산(4.8)은 같으므로, 발수·대상이 늘면 한 발당 피해는 그만큼 낮춰 계산한다. 능력은 승급 배율(×1.35)로 오르고, 사다리는 ‘보이는 모양’을 바꾼다. 값은 `crews.json`의 계열 기본값이다.

| 계열 | 항목 | 일반 | 희귀 | 영웅 | 전설 | 신화 |
| --- | --- | --- | --- | --- | --- | --- |
| 투척 | 폭탄 수 · 폭발 반경(px) | 1 · 20 | 1 · 23 | 2 · 23 | 2 · 26 | 3 · 26 |
| 직사 | 한 번에 연사 발수 | 3 | 4 | 5 | 6 | 8 |
| 관통 | 작살 수 · 최대 관통 | 1 · 4 | 1 · 6 | 2 · 6 | 2 · 8 | 3 · 8 |
| 물수제비 | 튀는 횟수 | 3 | 4 | 5 | 6 | 8 |
| 수중 | 장판 반경(px) · 지속(초) | 16 · 2 | 18 · 2.5 | 20 · 3 | 22 · 3.5 | 24 · 4 |
| 공중 | 타격 지점 수 | 2 | 3 | 3 | 4 | 5 |
| 강습 | 부채꼴 각도 · 넉백(px) | 60° · 4 | 70° · 5 | 80° · 6 | 90° · 7 | 110° · 8 |
| 충격 | 밀어내기(px) · 기절(초) | 10 · 0 | 12 · 0.3 | 14 · 0.5 | 16 · 0.7 | 20 · 1.0 |

- 발사 간격은 계열 기본값에서 바꾸지 않는다(투척 1.3초, 직사 0.9초마다 연사, 관통 1.6초, 물수제비 1.5초, 수중 1.8초, 공중 2.2초, 강습 1.2초, 충격 3초). 빠르기는 배의 돛 강화가 맡는다.
- 모든 값은 4.8절 상한(범위 7마리째부터 50%, 연쇄·관통 감쇠 10%)을 따른다.

#### 4.3.3 성장 수치

아래 값은 가상 플레이어 200명을 하루 40분 접속 + 오프라인 8시간 두 번 기준으로 간단히 시뮬해 맞춘 1차값이다. M1에서 `game_cli sim`으로 다시 검증한다.

| 항목 | 일반 | 희귀 | 영웅 | 전설 | 신화 |
| --- | --- | --- | --- | --- | --- |
| 레벨 1 올리는 경험치 | 1 | 3 | 6 | 20 | 30 |
| 이 등급 카드의 경험치 | 1 | 4 | 15 | 60 | - |
| 다음 등급 승급 카드 | 3 | 6 | 10 | 20 + 증표 50 | - |
| 승급 골드 | 처치 골드 × 100 | × 300 | × 1,000 | × 3,000 | - |
| 소환 확률 | 65% | 27% | 7% | 1% | 없음 |
| 보스 드롭 카드 등급 | 80% | 17% | 2.8% | 0.2% | 없음 |

- 승급 골드는 ‘그때 스테이지의 일반 몬스터 처치 골드’에 비례해 언제나 비슷한 무게로 느껴지게 한다.

**카드가 들어오는 길**

| 수급원 | 양 | 누구의 카드 |
| --- | --- | --- |
| 소환 | 1회 1장 (하루 약 15\~20회: 보스 젬 + 광고 + 일일 퀘스트) | 40명 중 무작위 |
| 보스 처치 | 스테이지 1\~10은 2장, 이후 `1 + floor(스테이지 / 150)`장 | 출전 중인 선원 중 무작위 |
| 오프라인 보상 | 8시간 기준 3장(비례) | 출전 중인 선원 |
| 보물상자 | 광고 보상 선택지 중 하나 | 출전 중인 선원 |
| 증표 상점 | 증표 10 = 카드 1장 | 플레이어가 고름 |

보스·오프라인 카드를 출전 선원에게 몰아주는 것이 핵심이다. 자주 쓰는 선원이 꾸준히 자라는 것이 보이고, 소환은 새 선원과 대박을 맡는다.

**시작 선원과 첫 승급**: PB와 같이 옥토·톡으로 시작한다. 처음 14장의 보스 카드는 옥토에게, 항상 일반 등급으로 간다(일반 Lv1→15 경험치 14 = 카드 14장). 빨리 차지 않게 보스 처치 몇 번마다 1장씩 나눠 준다(간격은 sim으로, 2026-10-14 결정). 그래서 첫 승급(옥토 일반 → 희귀)은 운과 상관없이 플레이 30\~40분에 반드시 일어난다.

**시뮬 결과와 목표**

| 사건 | 시뮬 중앙값 | 목표 범위 |
| --- | --- | --- |
| 첫 승급 | 튜토리얼로 고정 | 30\~40분 |
| 첫 전설 선원 보유 | 2일 | 1\~4일 |
| 승급으로 만든 첫 전설 | 5일 | 4\~8일 |
| 첫 신화 | 31일 | 4\~8주 |

첫 신화가 목표보다 조금 빠르다. M1 시뮬에서 신화 승급 카드(20장)와 전설 구간 경험치(20)를 먼저 조정한다.

| 계열 (PB와 같은 이름) | 배에서 나가는 발사체 | 범위 형태 | 스킬 (자동, 쿨타임) | 예시 선원 |
| --- | --- | --- | --- | --- |
| 투척(lob) | 포물선 폭탄 | 무리 한가운데 원형 폭발 | 포탄 비 5발 (8초) | 옥토, 볼케 |
| 직사(direct) | 총탄 연사 | 가장 가까운 적 단일, 치명타 강화 | 가장 강한 적 저격 5발 (6초) | 본즈, 볼트 |
| 관통(pierce) | 작살 | 한 줄을 화면 끝까지 관통 | 작살 3줄 동시 (8초) | 핀, 모비 |
| 물수제비(skip) | 튀는 돌·얼음 | 연쇄 | 연쇄 8회 + 끝에 물보라 (10초) | 핑구, 오르카 |
| 수중(underwater) | 어뢰·기뢰 | 물속으로 가다 폭발, 장판 지속피해 | 기뢰밭 깔기 (9초) | 젤리, 크라키 |
| 공중(air) | 폭격·번개·유도탄 | 무작위 여러 지점, 공중 적 우선 | 폭풍 번개 연쇄 (9초) | 윈, 만타 |
| 강습(assault) | 배 앞으로 뛰어드는 물기·베기 | 배 앞 부채꼴, 배에 붙은 적 처리 | 회전 베기 돌진 (7초) | 샤키, 데비 |
| 충격(shock) | 넓은 충격파 | 무리 전체를 뒤로 밀고 기절, 피해는 낮음 | 큰 파도로 화면 전체 밀어내기 (12초) | 톡, 램프 |

충격 계열은 PB처럼 ‘밀어내는’ 역할이다. 무리가 배에 닿지 못하게 밀어내면 다른 선원의 범위 공격에 더 오래 묶인다.

전설 선원의 스킬은 범위가 화면 전체다. 전설을 뽑았을 때 화면이 확 달라지는 것이 소환 동기다.

### 4.4 핵앤슬래시 전투

적을 한 마리씩이 아니라 무리로 보내고, 범위 공격으로 한 번에 쓸어버리는 순간을 반복해서 만든다. 플레이어가 조작하지 않아도 화면이 계속 터지는 것이 목표다. 미리보기는 `이미지참고용\해적도트원정대_전투_v0.3\battle_ship.gif`.

**전장 구성**: 내 배는 왼쪽에 멈춰 있고, 몬스터 무리가 오른쪽에서 바다(물위·물속)와 하늘(갈매기 등)로 몰려온다. 화면에서 움직이는 것은 배, 적, 발사체, 이펙트뿐이다. 선원은 화면 아래 슬롯에 초상으로 보이고, 발사할 때 슬롯이 번쳭이며 남은 쿨타임이 어두운 덮개로 표시된다. 적이 배에 닿으면 배 HP가 깎인다.

**무리**

- 한 파 = `min(14, 6 + floor(스테이지 / 10))`마리. 스테이지당 3파 후 보스.
- 마리당 HP는 낮게(한 파 총 HP = 기존 단일 몬스터 HP × 마리 수 × 0.6). 범위 공격 한 방에 여러 마리가 동시에 터지도록.
- 동시 처치 보너스: 0.5초 안에 잡은 수에 따라 문구와 골드 +10%/마리. 2 더블, 3 트리플, 5 학살!, 10 해적왕!

**스킬과 궁극기**

- 모든 선원은 계열별 자동 스킬 1개(4.3 표). 쿨타임이 돌면 알아서 쓴다.
- **함성 게이지**: 처치할 때마다 차고, 가득 차면 선장의 궁극기가 화면 전체에 터진다. 기본은 자동 발동, 원하면 버튼을 눌러 직접 터뜨릴 수 있다(유일한 선택적 조작).
- 궁극기는 선장 계열을 따른다: 해일(물수제비), 포탄 비(투척), 번개 폭풍(공중), 유령선 돌격(강습) 등 8종.
- 스킬은 코드가 아니라 `skills.json` 데이터다: 범위 모양(원 반지름, 직선 폭, 연쇄 횟수, 부채꼴 각도), 피해 배율, 쿨타임, 이펙트 id. 선원 40명을 더해도 코드는 늘지 않는다.

**타격감 규칙** (렌더 레이어에서 처리, 수치는 `juice.json`)

| 요소 | 언제 | 값 |
| --- | --- | --- |
| 히트스톱(멈춤) | 치명타 / 4마리 이상 동시 처치 / 궁극기 | 40ms / 70ms / 120ms |
| 화면 흔들림 | 범위 폭발 / 궁극기 / 보스 처치 | 2px·150ms / 4px·400ms / 6px·500ms |
| 흰색 번쳭임 | 피격된 적 | 2프레임 |
| 넉백 | 돌격 베기 / 폭발 중심에서 바깥으로 | 4px / 6px |
| 데미지 숫자 | 일반 / 치명타 / 범위 합산 | 흰색 2배 / 노랑 3배 튀기 / 큰 숫자 1개 추가 |
| 처치 | 모든 적 | 파편 + 코인 분수 + 코인이 배로 빨려감 |
| 보스 처치 | 보스 | 0.3초 슬로모션 + 화면 플래시 + 코인 비 |
| 진동 | 치명타 / 궁극기 | 약 / 중 |
| 소리 | 타격 / 폭발 | 타격음 3종 무작위 + 피치 ±8% / 저음 레이어 |

- 히트스톱은 코어가 ‘멈춘 틱 수’로 내보낸다. 시뮬과 화면이 같이 멈춰서 리플레이 결과가 바뀌지 않는다.
- 가독성 상한: 동시 이펙트 40개, 데미지 숫자 24개(넘치면 오래된 것부터 합침). 객체 풀링으로 프레임당 메모리 할당 0.
- 설정에서 흔들림·번쳭임·진동을 각각 끌 수 있다(접근성, 저사양 기기).

### 4.5 오래 키우는 재미

규칙은 늘리지 않고, ‘다음 목표’를 시간 단위별로 겹쳐 둔다. 화면 상단에는 항상 가장 가까운 목표 하나가 진행 막대로 보인다(예: ‘범선 승급까지 스테이지 4’).

| 주기 | 장치 | 내용 |
| --- | --- | --- |
| 수 초 | 동시 처치 문구, 강화 버튼 연속 누르기 | 4.4의 타격감 |
| 수 분 | 보스, 배 부위 25레벨 도약 | 효과 ×2 + 외형 변화 |
| 수 시간 | 배 승급, 해역 이동 | 50스테이지마다 새 해역: 산호초 → 폭풍해 → 빙하해 → 화산해 → 심해 → 유령해. 배경·적·BGM·해역 보스가 바뀐다 |
| 하루 | 환생(보물지도), 일일 퀘스트 4개, 출석 | 아래 참고 |
| 수 주 | 도감 40명, 전설 수집, 유령선 승급 | 도감 5명마다 전체 공격력 +3% |
| 장기 | 주간 랭킹 (2차) | 8장 |

**환생: 보물지도**

- 스테이지 40 이상에서 가능. 스테이지·골드·배 강화를 초기화하고 지도 조각 `floor((최고스테이지 - 35)^1.4)`개를 받는다.
- 조각 1개당 전체 피해·골드 +5%(합산). 선원·도감·젬은 유지한다.
- 환생 직후 5분 안에 이전 최고의 30% 지점까지 빠르게 회복되도록 밸런스한다. ‘다시 시작해도 금방 따라잡는다’는 느낌이 환생을 누르게 한다.
- 환생 버튼에는 ‘지금 하면 조각 N개, 다음 조각까지 스테이지 M’을 표시한다.

**매일**

- 일일 퀘스트 4개(처치 500, 강화 30회, 소환 1회, 광고 1회) → 퀘스트마다 젬 10(합계 40, 2026-10-14 결정).
- 출석 7일: 젬 20·20·30·30·40·50, 7일차 영웅 확정 소환 1회. 빠져도 초기화하지 않는다(2026-10-14 결정).
- 7일 출석: 7일차 영웅 이상 소환권.
- 로컬 알림(무료, 서버 없음): 오프라인 보상이 8시간으로 가득 찼을 때 1회. 하루 최대 1회, 설정에서 끔.

### 4.6 보상형 광고 유도 장치

광고는 강제하지 않고, ‘보면 이득이 숫자로 보이는 선택지’를 하루 여러 번 자연스럽게 만난다. 가장 강한 장치는 순풍 버프와 보물상자다.

| 장치 | 언제 나오나 | 보상 | 하루 한도 |
| --- | --- | --- | --- |
| 떠내려오는 보물상자 | 4분마다 바다 위로 둥둥 (40초 뒤 가라앉음) | 탭하면 골드 2분치, 광고 보면 골드 ×5 **또는** 젬 30 중 플레이어가 고름(= 소환 1회, 2026-10-14 결정) | 10회 |
| 순풍 버프 | 상단 돛 아이콘, 항상 | 30분간 골드·전투 속도 ×2, 최대 4시간 누적 | 8회 |
| 오프라인 보상 | 복귀 팝업 | ×2 | 복귀당 1회 |
| 함포 지원 | 보스 실패 팝업 | 30초간 피해 +30%로 즉시 재도전 | 10회 |
| 무료 소환 | 소환 탭 | 소환 1회 | 5회 |
| 일일 퀘스트 | 퀘스트 목록 | 퀘스트 조건 ‘광고 1회’ | - |

규칙:

- 버튼에는 항상 이득을 숫자로 쓴다(‘광고 보고 ×5 · 12.4K’). ‘광고 보기’만 쓰지 않는다.
- 첫 광고 제안은 플레이 3분 뒤 첫 보물상자에서. 튜토리얼 중에는 내보이지 않는다.
- 광고가 로드되지 않았으면 버튼을 숨기고 기본 보상만 남긴다. 실패 후 보상 없음 같은 나쁜 경험을 만들지 않는다.
- 한도와 보상은 `ads.json`에 둔다. 광고 하루 총 상한 25회. 광고 제안은 팝업으로 띄우지 않고 아이콘·버튼으로만 둔다(복귀 시 오프라인 보상 창 하나만 예외).
- 2차 IAP 후보: ‘광고 제거 패스’ = 광고 보상을 버튼 한 번에 즉시 지급.

### 4.7 오프라인 보상

- 보상 = `현재 스테이지 초당 골드 추정치 × min(경과 시간, 8시간) × 오프라인 효율`. 전투를 돌리지 않고 추정식으로 계산해 복귀 즉시 표시한다.
- 오프라인 효율(`meta.json offline.efficiency`)은 8시간 보상이 ‘다음 강화 3\~8회분’(7.2)이 되도록 시뮬로 맞춘다. 켜 두는 쪽이 확실히 이득이게 하는 장치다(2026-10-14 결정).
- 초당 골드 추정 = `한 파 골드 / (한 파 HP ÷ 원정대 DPS + 이동 시간)`. 보스는 넘지 않는다.
- 시계 조작 방어: 마지막 저장 시각보다 현재 시각이 이전이면 0, 8시간 상한.

### 4.8 밸런스 안전장치

같은 등급·같은 레벨이면 40명 모두 같은 ‘전투력 예산’을 갖는다. 선원마다 다른 것은 범위 모양과 연출뿐이다. 전설·신화의 고유 스킬도 화려함은 크게, 예산은 같게 만든다(화면 전체 공격이면 대상당 피해가 낮다).

**파워 예산 측정**

- 기준 시나리오 2개에서 60초 동안의 피해량을 잰다: (A) 무리전 — 12마리가 계속 몰려옴, (B) 보스전 — 큰 적 하나.
- 선원 점수 = (A 점수 + B 점수) / 2. 충격 계열은 밀어내기·기절로 늘어난 다른 선원의 피해량과 줄어든 배 피해를 합쳐 환산한다.
- 모든 선원의 점수는 같은 등급·레벨 중앙값의 **±10% 안**이어야 한다.

**계열 상성 (한 계열이 독주하지 못하게)**

- 범위 계열(투척·수중·공중·강습·충격)은 무리전에 강하고 보스전에 약하다. 단일 계열(직사·관통)은 반대다. 물수제비는 중간이다.
- 스테이지는 무리 파와 보스가 번갈아 나오므로, 한 계열만 모으면 오히려 느려진다.
- **편성 규칙**: 같은 계열은 최대 2명(수동 편성도 같은 상한 — 넘기면 거절). ‘자동 편성’ 버튼은 파워 순으로 고르되 같은 상한을 지켜 균형 잡힌 조합을 만든다.

**상한과 계산 규칙**

| 항목 | 규칙 |
| --- | --- |
| 최종 피해 | `기본 × 레벨 배율 × 승급 배율 × 배 등급 × (1 + 모든 % 보너스의 합)`. 곱하는 항목은 이 5개로 고정하고, 새 보너스는 모두 마지막 합에만 더한다 |
| 치명타 | 확률 최대 50%, 배율 ×2 고정 |
| 속도 | 공격 속도 배율 최대 ×2.5, 스킬 쿨타임 최소 1.5초 |
| 범위 | 한 번에 6마리를 넘게 맞히면 7번째부터는 피해 50% |
| 연쇄·관통 | 한 번 튀거나 뚫을 때마다 피해 10%씩 감소, 연쇄 최대 8 |
| 버프 | 같은 종류는 가장 큰 것 하나만 적용(중복 없음) |
| 승급 | 한 번에 ×1.35. 가장 큰 도약이 여기라 이 값 외의 곱셈은 만들지 않는다 |

**자동 검사 (하네스)**

- `game_cli balance crews`가 40명 × 5등급 × 대표 레벨(15·30·45·60·75)의 점수표를 만든다. 하나라도 ±10%를 벗어나면 실패한다.
- 가능한 6명 조합을 무작위로 많이 뽑아, 상위 1% 조합이 중앙값의 ×1.3을 넘으면 실패한다(시너지 폭주 방지).
- 선원·스킬 테이블을 바꾼 PR은 점수표를 첨부한다. `check.sh --full`과 야간 CI에서 돈다.
- 출시 후 조정은 강한 쪽을 내리기보다 약한 쪽을 올린다. 아끼는 선원이 약해지는 상실감이 이탈로 이어지기 때문이다.

### 4.9 이탈 방지와 피로 관리

이탈은 ‘뭘 해야 할지 모를 때’, ‘막혔을 때’, ‘지루할 때’, ‘귀찮을 때’ 일어난다. 시점별로 하나씩 막되, 해결책이 새 의무를 만들지 않게 한다.

| 시점 | 이탈 원인 | 장치 |
| --- | --- | --- |
| 첫 3분 | 뭘 하는 게임인지 모름 | 손가락 안내 3번(강화 → 보스 실패 → 강화 후 성공). 첫 판에 무리가 한 번에 터지는 장면을 보여준다 |
| 첫 10분 | 소환의 재미를 못 느낌 | 첫 10연 소환 무료 + 영웅 1장 확정. 영웅 승급 연출을 바로 보여준다 |
| 첫날 | 보스에 막힘 | 막힌 지 3분이면 ‘이것부터 강화’ 버튼 하나만 반짝인다. 힘이 충분해지면 보스에 자동 재도전(설정에서 끔) |
| 2\~3일 | 반복이 지루함 | 50스테이지마다 새 해역(배경·적·음악), 배 승급, 화면 위 ‘다음 목표’ 막대 |
| 1주 | 성장이 느려짐 | 환생(5분 안에 이전 30% 지점 회복), 영웅·전설 승급, 도감 보너스 |
| 매일 | 강화 버튼 연타가 귀찮음 | **자동 강화**(스테이지 20 해금): 골드를 가장 효율 좋은 순서로 알아서 쓴다. 카드는 일괄 합치기 |
| 매일 | 화면이 피곤함 | 흔들림·번쳭임·진동 끄기. 2분 입력이 없으면 절전 모드(화면 어둡게, 30fps, 전투는 계속) |
| 다시 오기 | 3일 이상 안 들어옴 | 복귀 선물(소환 5회, 순풍 2시간). 안 들어온 동안 잊은 것은 없다 |

**피로 금지 규칙** (스펙 리뷰에서 확인)

- **놓치면 사라지는 보상 금지**: 출석은 하루 빠져도 다음 날 이어서 받는다. 연속 기록 초기화 없음.
- **하루 할 일은 4개 이하**: 일일 퀘스트는 평소처럼 하면 자동으로 달성된다.
- **탭 4개 고정**: 항해(전투)·배·선원·소환. 새 기능은 기존 탭 안에 넣고, 탭을 늘리려면 하나를 없앤다.
- **빨간 점은 지금 눌러서 이득인 것에만**, 탭마다 하나.
- **팝업은 접속 때 최대 1개**(오프라인 보상). 나머지는 아이콘으로.
- **알림은 하루 최대 1개.**
- **시간 제한으로 초조하게 만드는 이벤트는 1차에 넣지 않는다.**

**이탈을 재는 방법**: Analytics에 ‘마지막으로 본 화면’, ‘마지막 스테이지’, ‘막힌 시간’을 남긴다. D1·D7 이탈자가 몰린 스테이지와 화면이 다음 업데이트의 우선순위다.

### 4.11 해역과 적

해역은 50스테이지마다 바뀌고, 해역마다 적 역할을 하나씩 새로 소개한다. 적 규칙은 늘 한 줄로 설명할 수 있을 만큼 단순하게 둔다.

**적 역할 6가지**

| 역할 | 규칙 | 잘 맞는 계열 |
| --- | --- | --- |
| 기본 | 평범한 속도·체력 | 모두 |
| 빠름 | 이동 1.6배, 체력 0.6배 | 직사·공중 |
| 단단함 | 이동 0.6배, 체력 2배 | 관통·직사 |
| 공중 | 하늘 줄로 날아옴, 수중·강습에 안 맞음 | 공중·직사 |
| 분열 | 처치되면 작은 적 2마리로 나뉨 | 투척·수중 |
| 부활 | 처음 처치되면 1번 일어남 | 범위 계열 |

**해역**

| 해역 | 스테이지 | 새 적 역할 | 적 (16px) | 25스테이지 중간 보스 | 해역 보스 (50스테이지) |
| --- | --- | --- | --- | --- | --- |
| 산호초 | 1\~50 | 기본·빠름·공중 | 꽃게, 피라냐, 해파리, 갈매기 | 약탈선(작은 적 해적선) | 대왕 소라게: 껍질 정면 피해 50%, 위에서 떨어지는 투척·공중은 그대로 |
| 폭풍해 | 51\~100 | 단단함 | 성게, 날치, 폭풍 갈매기, 복어 | 폭풍 해적선 | 번개 가오리: 10초마다 보호막, 관통이 깬다 |
| 빙하해 | 101\~150 | 분열 | 얼음게, 펭귄 떼, 바다표범, 눈갈매기 | 쇄빙선 | 빙산 바다코끼리: 얼음 방패, 충격이 밀어내면 깨진다 |
| 화산해 | 151\~200 | (복합) 단단함+분열 | 용암게, 불가사리, 화산 거북, 불새 | 화염 해적선 | 용암 고래: 주기적으로 용암을 뿜어 배 피해, 처치 속도 싸움 |
| 심해 | 201\~250 | 부활 | 아귀, 심해 오징어, 관해파리, 곰치 | 심해 잠수함 | 크라켄: 촉수 4개를 먼저 끊어야 몸통이 맞는다 |
| 유령해 | 251\~300 | (복합) 부활+공중 | 해골 선원, 유령 해파리, 저주 갈매기, 망령 | 유령선 | 유령 함대 제독: 잡몹을 계속 부르는 보스, 범위 계열이 빛난다 |

- 보스마다 "이 계열이 잘 먹힌다"는 약점 표시를 보스 이름 옆에 아이콘으로 보여준다. 약점 계열로 편성을 바꾸면 유리하지만, ‘자동 편성’도 계열을 섞으므로 꼭 바꿀 필요는 없다.
- **300스테이지 이후 (무한 항해)**: 해역 6개를 다시 돈다. 바퀴마다 적 체력·골드 곡선은 이어지고, 적에게 등급 테두리(희귀→영웅→전설)가 붙어 눈으로 구분된다. 새 그림 없이 콘텐츠를 늘린다.
- 해역 데이터는 `regions.json`, 적은 `enemies.json`(역할, 배율, 스프라이트)에 둔다.

### 4.12 화면 구성과 튜토리얼

세로 화면 하나에서 전장은 항상 위쪽에 보이고, 아래쪽 절반만 탭에 따라 바뀐다. 강화나 합치기를 하는 동안에도 배가 싸우는 모습이 계속 보여야 방치형의 손맛이 끊기지 않는다.

**화면 배치 (위에서 아래로)**

| 영역 | 높이 | 내용 |
| --- | --- | --- |
| 상단 바 | 약 6% | 골드, 젬, 해역 이름 + 스테이지, 설정 |
| 목표 막대 | 약 3% | 가장 가까운 목표 하나 (예: ‘범선 승급까지 스테이지 4’) |
| 전장 | 약 38% | 배·무리·이펙트, 함성 게이지, 순풍 남은 시간, 보스 타이머, 보스 도전 버튼(파밍 중), 보물상자, 퀘스트·출석 아이콘 1개 |
| 선원 슬롯 줄 | 약 8% | 출전 선원 초상 최대 6칸, 쿨타임 덮개. 함성이 차면 선장 칸이 빛나고 누르면 궁극기 |
| 탭 패널 | 약 37% | 아래 표 |
| 탭 바 | 약 8% | 항해 · 배 · 선원 · 소환 |

**탭 패널**

| 탭 | 내용 |
| --- | --- |
| 항해 | 해역 지도(해역 6개 진행), 환생 버튼(스테이지 40부터), 패널을 접어 전장을 크게 보기 |
| 배 | 부위 5줄(아이콘·레벨·효과·비용 버튼, 꾹 누르면 연속), 자동 강화 켜기, 배 등급 진행 막대 |
| 선원 | 일괄 합치기 버튼, 보유 선원 격자(초상·등급 테두리·레벨·카드 게이지·승급 가능 빨간 점), 정렬, 보유 효과 합계, 도감 진척. 선원을 누르면 상세 창: 발사체 설명, 다음 승급 때 바뀌는 모습 미리보기, 승급 버튼 |
| 소환 | 1회·10회 버튼, 광고 무료 소환(남은 횟수), 확률표, 천장 진행 막대, 증표 상점 |

**팝업은 3가지뿐**

- 오프라인 보상: 접속할 때 하나. 광고 ×2 버튼.
- 승급 연출: 전체 화면 3초, 선원이 크게 나오고 바뀐 발사체를 한 번 쏴 보인다. 탭하면 넘긴다.
- 소환 결과: 카드 뒤집기. 전설은 금빛, 이후 승급으로만 오는 신화 연출은 승급 연출에서 쓴다.

**설정**: 언어(시스템·한국어·English), 배경음·효과음, 진동·흔들림·번쩍임, 절전 모드, 자동 보스 도전, 자동 강화, 알림, 크레딧(라이선스), 버전(운영자 빌드에서 5번 누르면 운영자 모드).

## 5. 데이터 설계

밸런스 수치는 코드가 아니라 JSON 데이터 테이블에 둔다. 에이전트가 수치를 바꿔도 로직은 건드리지 않고, 밸런스 시뮬레이터가 변경 전후를 비교할 수 있다.

### 5.1 데이터 테이블 (`packages/game_data/tables/`)

| 파일 | 내용 | 담당 레인 (6.8절) |
| --- | --- | --- |
| `crews.json` | 선원 40명: id, 계열, 등급별 발사체 수치, 초상, l10n 키. 성장은 \`growth.json\`(레벨 경험치, 승급 재료, 등급 배율, 보유 효과, 증표 교환율) (도트 팩의 `characters.json`에서 생성) | 경제 |
| `rarities.json` | 등급 계수, 소환 확률, 천장, 색 | 경제 |
| `ship_parts.json` | 부위 5종 수식, 비용, 최대 레벨, 25레벨 도약 | 경제 |
| `ship_tiers.json` | 배 등급, 승급 스테이지, 갑판 수, 피해 보너스 | 경제 |
| `skills.json` | 계열·선원별 스킬: 범위 모양, 배율, 쿨타임, 이펙트 id, 궁극기 | 전투 |

규칙:

- 텍스트는 테이블에 넣지 않고 l10n 키만 둔다(`hero.knight.name`). 문구는 ARB에 ko/en 두 벌.
- 모든 테이블은 로드 시 검증한다: 확률 합 = 1.0, 증가율 > 1, 참조하는 스프라이트·l10n 키 존재. 실패하면 테스트가 깨진다.
- 테이블은 앱에 포함해 배포한다. 원격 조정은 2차 이후.

### 5.2 세이브 스키마

단일 JSON 파일(`save.json`)에 저장한다. 예시(v1):

```json
{
  "schemaVersion": 1,
  "savedAt": "2026-11-01T12:34:56Z",
  "playerId": "local-uuid-v4",
  "rngSeed": 913377,
  "wallet": { "gold": "1.25e6", "gems": 140, "mapPieces": 0 },
  "progress": { "stage": 37, "wave": 2, "bestStage": 41, "farming": false, "rebirths": 0, "rage": 0.4 },
  "ship": { "parts": { "cannon": 52, "hull": 40, "sail": 18, "crowsnest": 12, "cargo": 9 } },
  "crews": { "octo": { "level": 15, "exp": 0, "cards": 2 }, "manta": { "level": 46, "exp": 3, "cards": 0 } },
  "tokens": 12,
  "summon": { "pityCount": 17 },
  "buffs": { "tailwindUntil": "2026-11-01T14:04:56Z" },
  "daily": { "date": "2026-11-01", "ads": { "chest": 3, "tailwind": 2 }, "quests": { "kill_500": 140 }, "attendanceDay": 4 },
  "collection": ["octo", "manta"],
  "settings": { "lang": "system", "autoUpgrade": true, "autoBoss": true, "powerSave": true, "bgm": true, "sfx": true, "vibration": true, "shake": true, "flash": true },
  "checksum": "sha256:…"
}
```

- **원자적 쓰기**: `save.tmp`에 쓰고 파일 이름을 바꾼다. 직전 본은 `save.bak`으로 보관한다.
- **저장 시점**: 강화·소환·보스 클리어 직후, 앱이 백그라운드로 갈 때, 그 외 10초마다.
- **체크섬**: 본문 해시. 맞지 않으면 `save.bak`으로 복구한다. 보안이 아니라 파일 손상 탐지용이다.
- **마이그레이션**: `schemaVersion`마다 `migrate_v1_to_v2()` 같은 순수 함수를 두고 순서대로 적용한다. 모든 과거 버전의 샘플 세이브를 `test/fixtures/saves/`에 보관하고, 최신 버전까지 올리는 테스트를 상시 돌린다. 스키마를 바꾸는 PR은 마이그레이션 + 픽스처 없이 통과하지 못한다.

### 5.3 큰 수

방치형은 골드가 수십 자리를 넘는다. `game_core`에 `BigNum`(가수 double + 지수 int) 값 타입을 두고 골드·HP·피해는 모두 이 타입을 쓴다.

- 연산: 더하기, 빼기, 곱하기, 나누기, 거듭제곱, 비교. 정규화로 가수를 \[1, 10) 안에 유지.
- 저장: 문자열 `"1.25e6"`. 불러올 때 검증.
- 표시: 1,000 미만은 정수, 이후 K·M·B·T, 그 뒤 aa·ab… 표기. 포맷터는 l10n과 무관하게 동일.
- 속성 테스트: 무작위 값 수천 개로 교환·결합법칙과 double 결과와의 오차를 확인한다.

## 6. 하네스 엔지니어링

코드는 Claude Code가 쓰고, 사람은 에이전트가 스스로 맞고 틀림을 알 수 있는 환경(하네스)을 만든다. 네 가지 원칙을 따른다.

1. **저장소가 유일한 기록**: 에이전트가 읽을 수 없는 결정(대화, 메모, 머릿속)은 없는 것과 같다. 설계·스펙·결정은 모두 `docs/`에 둘다.
2. **규칙은 문서가 아니라 기계로 강제**: “코어에서 Flutter를 쓰지 말 것”은 문장이 아니라 실패하는 검사 스크립트로 둔다.
3. **화면 없이 초 단위 피드백**: 게임 규칙은 순수 Dart라 에뮬레이터 없이 테스트·시뮬레이션으로 검증한다.
4. **에러 메시지가 고칠 방법을 말한다**: 검사가 실패하면 무엇을 어디로 옮기라는 문장을 출력해 에이전트가 그대로 따르게 한다.

### 6.2 AGENTS.md

짧은 지도로 유지한다. 자세한 내용을 다 넣으면 에이전트가 중요한 규칙을 놓치므로, 규칙 목록과 문서 위치만 적는다.

```markdown
# 해적도트 원정대 — 에이전트 가이드

## 시작 전에 읽을 것
- docs/lanes/<내 레인>.md — 내가 만질 수 있는 경로와 완료 기준
- docs/ARCHITECTURE.md — 레이어와 의존 규칙
- packages/game_core/lib/contracts.dart — 바꾸지 말 것. 필요하면 docs/contracts/requests/에 요청

## 레드라인 (위반하면 tool/check.sh 실패)
- 내 레인 경로(LANES.yaml) 밖의 파일을 수정하지 않는다
- game_core는 Flutter, dart:io, dart:ui를 import하지 않는다
- game_core에서 DateTime.now(), Random() 직접 호출 금지 → Clock, Rng 포트
- 밸런스 수치는 game_data/tables에만
- 화면 문구는 내 레인의 ARB(ko와 en 둘 다)에만. 한쪽만 있으면 실패
- 세이브 스키마 변경 = 마이그레이션 + 픽스처 필수

## 완료 조건
- tool/check.sh 통과
- 스펙의 수용 기준마다 테스트 1개 이상
- 새 문구는 ko/en 둘 다, 영어 화면 골든 1장 포함
- 새 기능은 운영자 모드에서 바로 불러볼 수 있게 (docs/GAME_DESIGN.md 6.10)
- 스토어 빌드에 운영자 코드가 남으면 실패
- 밸런스 테이블을 바꿨다면 balance 리포트를 PR에 첨부

## 자주 쓰는 명령
- tool/check.sh                 모든 검사 (목표 90초)
- dart run game_cli sim          밸런스 시뮬
- dart run game_cli export-events 렌더 레인용 이벤트 로그 갱신
```

### 6.4 피드백 루프

`tool/check.sh`는 빠른 것부터 순서대로 돌고 첫 실패에서 멈춘다.

1. 포맷 → 정적 분석 → 의존·금지 패턴 검사 (수 초)
2. game\_core, game\_data 단위 테스트 (10초대)
3. 시나리오 리플레이 테스트 (10초대)
4. 밸런스 스모크: 가상 플레이어 1명 × 게임 시간 2시간을 배속 시뮬 (30초 이내)
5. Flutter 위젯·골든 테스트 (`--full`일 때만)

CI(GitHub Actions)는 PR마다 `check.sh --full`을 돌리고, 매일 밤 가상 플레이어 100명 × 30일 밸런스 리포트를 만든다.

### 6.5 Claude Code 훅

| 훅 | 동작 | 목적 |
| --- | --- | --- |
| PostToolUse (Edit, Write) | 수정한 파일에 `dart format` + 해당 패키지 `dart analyze` | 작은 실수를 즉시 고침 |
| PreToolUse (Edit, Write) | `test/fixtures/saves/`, 골든 이미지 수정 차단 | 테스트를 통과시키려고 기대값을 고치는 것을 막음. 갱신은 사람이 명령으로만 |
| Stop | `tool/check.sh` 실행, 실패하면 종료를 막고 실패 내용을 돌려줌 | “다 했습니다”가 실제 통과를 뜻하게 함 |

### 6.6 에이전트가 쓰는 도구 (game\_cli)

- `sim --seed 1 --hours 8 --policy greedy` — 헤드리스로 플레이하고 스테이지 도달 시간, 벽 구간, 재화 잔액을 JSON과 표로 출력.
- `replay scenarios/boss_fail.yaml` — 시나리오 하나를 돌리고 기대 상태와 비교.
- `save inspect save.json` — 세이브 검증, 마이그레이션 결과 출력.
- `balance diff` — 테이블 변경 전후 시뮬 비교 리포트.

앱에는 테스트 기기용 운영자 모드를 둔다(6.10절). 사람이 기기에서 손맛·선원·밸런스를 확인할 때 쓴다.

### 6.7 작업 흐름과 역할

1. 스펙 작성: `docs/specs/<기능>.md`에 목적, 규칙, 수용 기준(Given/When/Then). 사람이 승인.
2. 실행 계획: 에이전트가 `docs/plans/active/`에 단계와 검증 방법을 적는다.
3. 테스트 먼저: 수용 기준을 시나리오·단위 테스트로 옮긴다(실패 확인).
4. 구현 → `check.sh` 통과.
5. PR: 변경 요약, 밸런스 리포트(해당 시), 계획을 `plans/done/`으로 이동.
6. 사람 확인: 실기기에서 손맛, 아트, 광고만 본다. 로직은 테스트를 믿는다.

| 사람 (ew.park) | 에이전트 (Claude Code) |
| --- | --- |
| 스펙·우선순위 승인, ADR 결정 | 코드, 테스트, 시나리오, 문서 갱신 |
| 계정·키·빌드 서명·스토어 등록 | check.sh 통과까지 반복 |
| 골든·픽스처 갱신 승인 | 밸런스 리포트 생성 |
| 실기기 감각 확인, 에셋 선정 | 주 1회 정리 작업(문서·코드 불일치, QUALITY.md 갱신) |

### 6.8 병렬 개발 (세션 분할)

병렬로 가되, 첫 1\~2일은 세션 하나가 ‘계약’만 만들고 고정한다. 바이브코딩에서 병렬 세션이 느려지는 원인은 코드 작성이 아니라 서로의 파일을 건드리는 충돌과 서로를 기다리는 대기인데, 계약(인터페이스)과 가짜 데이터(픽스처)를 먼저 고정하면 둘 다 없어진다. 그래서 모듈을 나누는 기준도 기능이 아니라 ‘폴더 소유권’이다.

| 레인 | 소유 경로 | 기다리지 않고 쓰는 입력 | 완료 기준 | 시작 |
| --- | --- | --- | --- | --- |
| 전투 코어 | `game_core/lib/src/battle/`, `skills·waves·regions.json` | 계약, 테이블 스키마 | 시나리오 통과, `export-events`로 이벤트 로그 생성 | 1차 |
| 경제·성장 | `game_core/lib/src/economy/`, `game_cli/sim`, 경제 테이블 | 계약, 전투 DPS는 추정식 | 밸런스 목표(7.2절) 통과 | 1차 |

| 아트 | `apps/game/assets/`, `tools/art/` | 도트 팩 v0.2(32px), 스프라이트 규격 | v0.2: 전설 8명 보정, 적 20종, 배 4단계, 해역 6개 | 2차 |

**충돌을 막는 규칙**

1. **폴더 소유권**: `LANES.yaml`에 레인별 경로를 적고, `check_lane.dart`가 브랜치 `lane/<이름>/*`의 변경 파일이 소유 경로 밖이면 실패시킨다. 예외는 자기 레인의 `docs/plans/`, `docs/contracts/requests/`뿐.
2. **계약 변경은 요청으로만**: 레인이 `contracts.dart`를 바꾸고 싶으면 `docs/contracts/requests/`에 요청서를 쓰고, 임시 어댑터로 계속 작업한다. 통합 세션이 하루 한 번 모아서 반영한다.
3. **다국어 충돌 없음**: ARB를 레인별 파일(`parts/<레인>.ko.arb`, `.en.arb`)로 나누고 키 접두어(`battle.`, `ui.` 등)를 분리한다. `merge_arb.dart`가 빌드 전에 합치고, ko/en 키가 다르면 실패한다.
4. **픽스처로 대기 제거**: 렌더는 전투 이벤트 로그를, UI는 샘플 상태를 입력으로 개발한다. 전투 레인이 바뀌면 `export-events`로 로그만 갱신한다.
5. **통합 순서 고정**: 매일 계약 → 코어(전투, 경제) → 렌더·UI → 플랫폼·아트 순으로 머지하고, 각 레인은 다음 날 아침 main에서 리베이스한 뒤 시작한다.
6. **세션 시작 명령**: 각 세션은 `/lane-start <레인>`으로 시작해 `docs/lanes/<레인>.md`와 소유 경로를 불러온다. 레인 밖 맥락을 읽지 않아서 컨텍스트가 짧고 빠르다.

**동시 세션은 4개로 고정한다.** 에이전트는 6개도 돌릴 수 있지만, 스펙 승인·실기기 확인·머지 판단을 하는 사람이 한 명이라 그 이상은 리뷰 대기로 오히려 느려진다. 레인 6개는 세션 4개가 시기별로 나눠 맡는다(6.9절).

| 때 | S2·S3·S4 | S1 (선장) | 사람 |
| --- | --- | --- | --- |
| 시작 | `git merge main`으로 전날 통합본을 받고 `/lane-start` | 계약 변경 요청 확인 | 오늘 레인별 목표 한 줄씩 지시 |
| 작업 중 | 자기 경로만 수정, 막히면 계약 요청서 작성 후 임시 어댑터로 계속 | 전투 레인 작업 | 질문에만 답함 |
| 끝 | `tool\check.bat` 통과 → 커밋 → 계획 파일에 한 일·내일 할 일 기록 | 정해진 순서로 머지: 경제 → 렌더 → UI, 머지마다 `check.sh` | 실기기 손맛 확인, 승인 |

**충돌을 피하는 세부 규칙**

- 실기기·에뮬레이터는 S4만 쓴다. S3는 `flutter run -d chrome`과 골든 테스트로 확인해 기기 점유 충돌을 막는다.
- `main`에는 S1만 커밋·머지한다. 다른 세션은 자기 브랜치에만 커밋한다.
- 설계서 변경은 사람이 결정하고, 저장소의 `docs/GAME_DESIGN.md`도 같은 날 갱신한다(S1 담당). 설계서와 코드가 어긋나면 설계서가 기준이다.
- 한 세션이 오래 막히면 그 세션을 멈추고 다른 레인을 먼저 진행한다. 4개를 억지로 동시에 돌리지 않는다.
- 세션 4개는 Claude 사용량을 4배로 쓴다. 요금제 한도에 걸리면 S1·S2(코어)를 우선 살리고 S3·S4를 쉬게 한다.
- 검사 로직은 전부 Dart(`tool/check.dart`)로 작성하고, Windows에서는 `tool\check.bat`, CI(Linux)에서는 `tool/check.sh`가 같은 스크립트를 부른다. 문서에서 ‘check.sh’는 둘을 함께 가리킨다.

### 6.10 운영자 모드

테스트 기기에서 모든 선원을 모든 등급·레벨로 곧바로 시험할 수 있게 하는 숨은 패널이다. 처음부터 설계에 넣고, 0단계 계약에 운영자 명령(`OperatorCommand`)을 포함한다. 나중에 덧붙이면 코어 구조를 다시 고쳐야 하기 때문이다.

**켜는 법과 안전**

- 빌드 옵션 `--dart-define=OPERATOR=true`로 만든 내부 테스트용 빌드에서만 있다. 설정 화면의 버전 글자를 5번 누르면 열린다.
- 스토어 배포 빌드에는 코드 자체가 빠진다(상수 플래그로 컴파일 때 제거). CI가 배포 빌드에 운영자 문구·클래스가 남아 있으면 실패시킨다.
- 운영자 모드로 바꾼 세이브에는 표식을 남기고, 랭킹(2차)에는 제출하지 않는다.

**기능**

| 묶음 | 기능 |
| --- | --- |
| 선원 | 40명 전원을 아무 등급(일반\~신화)·레벨(1\~75)로 즉시 지정. 자동 편성을 끄고 슬롯에 직접 배치. 한 선원만 단독 출전. 스킬·궁극기 즉시 발동, 쿨타임 0. 프리셋 ‘계열별 대표 6명’, ‘전설 전원’, ‘신화 전원’ |
| 비교 | 선원 두 명을 같은 조건(무리전·보스전)에서 60초 돌려 피해량을 나란히 표시. 4.8절 점수와 같은 계산을 쓴다 |
| 전장 | 스테이지·해역 점프, 무리 크기·적 종류 지정, 보스 즉시 소환, 배 무적, 배속(일시정지·1프레임 진행·×1·×2·×4), 범위·히트박스 표시, FPS·이펙트 수 표시 |

| 경제 | 골드·젬·카드·증표 지급, 배 부위·배 등급 지정, 환생 즉시, 오프라인 시간 가짜 경과, 날짜 넘기기(일일 초기화·출석 테스트) |

| 언어 | ko/en 즉시 전환, 긴 문장 모드(문구 40% 늘려 잘림 확인) |
| 저장 | 세이브 내보내기·불러오기, `fixtures/states/`의 샘플 상태 불러오기, 초기화 |

**레인 분담**: 운영자 명령은 계약에 두고(S1), 명령 처리는 경제·전투 코어가(S1·S2), 범위·FPS 표시는 렌더가(S3), 패널 화면은 UI가(S4) 맡는다. 각 레인은 새 기능을 만들 때 그 기능을 운영자 모드에서 바로 불러볼 수 있게 하는 것까지를 완료 조건으로 한다.

### 7.2 밸런스 목표 (초기값)

가상 플레이어는 ‘가장 싼 강화 구매, 젬 쌓이면 소환, 보스 실패 시 60초 파밍 후 재도전’ 정책으로 플레이한다. 목표를 벗어나면 스모크는 경고, 야간 전체 시뮬은 실패로 처리한다.

| 지표 | 목표 범위 | 의도 |
| --- | --- | --- |
| 첫 보스 실패 | 플레이 1\~3분 | 튜토리얼에서 ‘실패 → 강화’ 루프 학습 |
| 첫 소환 가능 | 플레이 5분 이내 | 수집 동기 조기 노출 |
| 스테이지 10 | 6\~12분 | 초반 속도감 |
| 스테이지 40 (환생 해금) | **첫날 안**: 하루 40분 일정(20분 → 8시간 → 20분) sim에서 첫날 두 번째 접속이 끝나기 전(경과 8시간 40분 이내). 계속 접속이면 20분 이상 | 1일차 목표 (2026-10-14 S1 정리: '경과 1.5~3시간'은 첫 오프라인 구간이라 스테이지가 오를 수 없어 의도인 '1일차'로 판정) |

| 오프라인 8시간 보상 | 다음 강화 3\~8회분 | 복귀 직후 할 일이 있게 |
| 광고 가치 | 젬 광고 1회 = 소환 1회 | 보는 이유가 분명하게 |

성장 목표(첫 승급·첫 전설·첫 신화)는 4.3.3절 표를, 선원 간 균형은 4.8절 검사를 같은 야간 시뮬에서 함께 확인한다.

이 수치는 출시 후 Analytics의 실제 플레이 시간과 비교해 고친다.

## 8. 네트워크 확장 (랭킹)

랭킹은 Cloudflare Workers + D1로 만들고, 1차 코드에는 `LeaderboardPort` 인터페이스와 아무것도 안 하는 구현만 둔다. 2차에는 어댑터 하나와 랭킹 화면만 추가하면 된다. 게임 진행은 계속 로컬에서 돌고, 서버는 점수만 받는다.

### 8.1 포트 (1차에 만들어 둘 것)

```dart
abstract interface class LeaderboardPort {
  Future<void> submit(ScoreSubmission s);          // 신기록일 때만 호출
  Future<List<RankEntry>> top(Board board, {int limit = 100});
  Future<RankEntry?> me(Board board);
}

// 1차: NoopLeaderboard, 2차: CloudflareLeaderboard
```

게임 코어는 ‘최고 스테이지 갱신’ 이벤트만 내보낸다. 전송 실패는 큐에 담아 다음 실행 때 다시 보낸다. 네트워크가 없어도 게임은 멈추지 않는다.

### 8.2 서버 설계

| 항목 | 설계 |
| --- | --- |
| 보드 | 최고 스테이지(전체), 주간 최고 스테이지(월요일 00:00 KST 초기화), 전투력 |
| 식별 | 최초 등록 시 기기 UUID + 서버가 발급한 비밀키. 비밀키는 기기 보안 저장소에, 서버는 해시만 저장. 로그인 없음 |
| 닉네임 | 2\~12자, 금칙어 필터, 변경은 7일에 1회 |
| API | `POST /v1/register`, `POST /v1/scores`, `GET /v1/boards/{id}/top`, `GET /v1/boards/{id}/me` |
| D1 테이블 | `players(id, secret_hash, nickname, created_at, banned)`, `scores(player_id, board, value, season, submitted_at)` |

### 8.3 치팅 방지 (가볍게)

랭킹에 보상이 없으므로 완벽한 방어보다 명백한 조작을 걸러내는 수준으로 한다.

- **도달 가능성 검사**: 밸런스 시뮬으로 ‘가입 후 N시간에 도달 가능한 최대 스테이지’ 표를 만들어 서버에 넣는다. 이를 넘는 점수는 보류 처리한다. 결정론적 코어가 있어서 가능한 방법이다.
- **전송 제한**: 플레이어당 1분에 1회, 값은 이전보다 커야 함.
- **요약 동봉**: 점수와 함께 강화 레벨 합·대원 수·환생 횟수를 보내 서버가 전투력 계산과 대조한다.
- **수동 차단**: `banned` 플래그. 보류 점수는 관리용 로컬 스크립트로 검토.

### 8.4 무료 티어 안에서 버티기

Workers 무료는 하루 10만 요청이다. 활성 사용자 1명이 하루 평균 제출 3회 + 조회 6회를 쓴다고 보면 일 활성 사용자 약 1만 명까지 무료다. 이를 위해:

- 제출은 최고 기록 갱신 시에만 한다.
- 랭킹 조회는 클라이언트에서 5분 캐시한다.
- 한도에 가까워지면 Cron으로 상위 100명 JSON을 정적 파일로 만들어 배포하는 방식으로 바꾼다.

대안으로 Google Play 게임즈 리더보드와 Game Center는 서버 없이 무료지만, Android와 iOS 랭킹이 따로 나뉘고 화면을 우리가 꾸밀 수 없어서 채택하지 않는다.

## 9. 수익화와 규정

수익은 AdMob 보상형 광고만으로 낸다. 강제 전면 광고는 초반 이탈을 키우므로 넣지 않는다.

### 9.1 광고 배치

광고 배치와 한도는 4.6절을 따른다.

- 광고는 `AdsPort` 뒤에 둔다. 디버그·테스트에서는 즉시 보상하는 가짜 구현을 쓴다. 보상 지급은 광고 SDK의 보상 콜백에서만 한다.
- 한도와 보상량은 `economy.json`에 둔다. 하루 기준은 기기 현지 날짜다.
- 후일 IAP(광고 제거, 젬 패키지)를 위해 `PurchasePort` 자리만 만들어 둔다.

### 9.2 동의와 개인정보

- **UMP(유럽 등 동의)**: google\_mobile\_ads에 포함된 UMP로 첫 실행 시 동의를 받고, 완료 후에 광고를 초기화한다.
- **ATT(iOS)**: UMP 뒤에 추적 권한을 묻는다. 거부해도 비맞춤 광고로 동작한다.
- **개인정보처리방침과 app-ads.txt**: GitHub Pages(무료)에 둔다. 스토어 개발자 웹사이트를 그 주소로 등록해야 AdMob이 app-ads.txt를 찾는다.
- **Play 데이터 보안 양식 / App 개인정보 라벨**: 광고 ID, 크래시 로그, 앱 상호작용을 수집 항목으로 신고.

### 9.3 확률형 아이템

현재 설계에서는 젬을 돈으로 팔지 않으므로 법적 공개 의무 대상이 아니다. 2024년 3월 22일 시행된 제도는 무료 재화로만 얻는 아이템과 연 매출 1억 원 이하 사업자를 제외하지만, 무료 재화가 유료 재화와 교환되면 대상이 된다 ([ZDNet Korea](https://zdnet.co.kr/view/?no=20240222164405)).

그래도 처음부터 공개한다. 비용이 거의 없고, IAP로 젬을 팔기 시작하는 순간 의무가 생기기 때문이다.

- 소환 화면에 등급별 확률과 천장 규칙을 표시한다. 값은 `rarities.json`에서 직접 읽어 문서와 코드가 다를 수 없다.
- 테스트: 100만 회 소환 시뮬의 등급 비율이 표시 확률과 오차 0.2%p 이내인지 확인한다.

### 9.4 등급

Google Play와 App Store의 자체 등급 설문(IARC 등)으로 받는다. 판타지 전투, 혈흔 없음, 실제 돈 거래 없음으로 전체이용가에서 12세 사이가 예상된다. 랭킹 닉네임이 들어가면 사용자 간 상호작용 항목을 갱신한다.

## 10. 아트·사운드 조달

선원은 외부 에셋이 아니라 자체 IP인 Pirate Busters v0.24의 캐릭터 40명을 도트로 다시 그려 쓴다. 64px 1차본(도트 팩 v0.1)은 `D:\Projects\이미지참고용\해적도트원정대_도트_v0.1`에 있고, 같은 스크립트로 다시 굽을 수 있다.

**전장은 배 vs 몬스터다.** 선원은 전장에 나오지 않고 32×32 초상으로 슬롯·소환·도감 화면에서만 쓴다. 덕분에 선원 40명의 동작 프레임이 필요 없고, 아트 작업은 배·적·발사체·이펙트에 집중한다. 배와 적을 작게(적은 16px 안) 그려 한 화면에 무리 20마리 이상이 들어가고, 큰 범위 이펙트가 무리를 한 번에 쓸어버리게 한다. 미리보기와 스프라이트는 `이미지참고용\해적도트원정대_전투_v0.3`에 있다.

| 항목 | 규격 | 상태 |
| --- | --- | --- |
| 화면(논리) | 320×180: 전장 0\~148, 선원 슬롯 148\~180. 기기에 맞춰 정수배 확대 | 확정 |
| 내 배 | 약 60×46, 4단계(쪽배·범선·해적 군함·유령선) + 부위별 외형 3단계 | 1단계 임시본 |
| 적 | 16×16 안, 2프레임. 해역마다 4\~6종 | 6종 임시본(꽃게·해파리·피라냐·복어·성게·갈매기) |
| 보스 | 적 해적선, 해역 보스(약 48px) | 적 해적선 임시본 |
| 발사체 | 2\~7px. 계열 8종 | 포탄·총탄·작살·돌·어뢰 완료 |
| 이펙트 | 범위 폭발, 해일, 번개 등 8종 + 스킬·궁극기용 8종 | 8종 완료 |
| 선원 초상 | 32×32 한 장 (동작 프레임 없음) | 40명 완료, 전설 8명 보정 예정 |
| 해역 배경 | 320×148, 하늘·원경·바다 3층 | 산호초 임시본 |

외부에서 무료로 가져오는 것은 폰트와 소리뿐이다.

| 용도 | 출처 | 라이선스 | 비고 |
| --- | --- | --- | --- |
| 한글·영문 폰트 | [Galmuri](https://github.com/quiple/galmuri) | OFL 1.1 | 한글 지원 픽셀 폰트, 7\~15px |
| 효과음 | Kenney 오디오 팩, OpenGameArt CC0 | CC0 | CC-BY-SA는 쓰지 않음 |
| BGM | OpenGameArt CC0 챔튜내 | CC0 | 해역별 1곡 |
| 도트 편집 | Pixelorama (MIT) 또는 LibreSprite | 무료 | 수작업 보정용 |

도트 제작 규칙:

- **정수 배율 + nearest**로만 그린다. 화면 논리 해상도 320×180(세로 모드 전투 영역)을 기기에 맞춰 정수배 확대.
- **원본에서 다시 굽기**: Pirate Busters 원본이 바뀌면 `tools/pixelize.py`로 자동 변환을 다시 돌리고, 수작업 보정본은 `overrides/`에 둔다. 보정본이 있으면 자동본보다 우선.
- **연출은 코드로**: 그림자, 흰 번쳭임, 흔들림, 숫자, 색 교체(적·희귀도 색)는 엔진이 처리해 에셋 수를 늘리지 않는다.
- **화려함은 이펙트에 집중**: 캐릭터는 단순한 절차적 프레임을 쓰고, 타격감은 범위 이펙트·히트스톱·숫자가 만든다. 제한된 팔레트(불 5색, 물 5색, 전기 4색, 금 4색)를 공유해 통일감을 유지한다.

라이선스 관리도 하네스에 넣는다. `assets/LICENSES.json`에 파일별 출처·라이선스를 적고, 등록되지 않은 에셋이나 CC0·OFL·MIT 외 라이선스가 있으면 `check.sh`가 실패한다. 앱 설정 화면에는 이 파일로 크레딧을 자동 표시한다(OFL 폰트는 라이선스 표기 필요).

## 11. 마일스톤

약 15주 뒤 Android 정식 출시가 기준 일정이다. 각 단계는 완료 조건을 모두 만족해야 끝난다. 6.8절의 병렬 레인으로 M1\~M4가 겹쳐 진행되면 총 기간은 11주 안팎으로 줄어들 수 있다. 기간은 퇴근 후·주말 작업을 가정한 추정치다.

## 12. 리스크와 미결 사항

가장 큰 리스크는 개발이 아니라 홍보다. 광고비 0원으로는 스토어 검색과 커뮤니티가 유일한 유입 경로다.

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 유입 부족 (광고비 없음) | 설치가 안 나면 밸런스도 검증 불가 | ASO(‘도트’, ‘방치형’, ‘키우기’ 키워드), 플레이 영상 스토어 등록, 커뮤니티(인디 게임 게시판) 개발일지 |
| 도트 품질 | 자동 변환 도트는 가는 선이 뭉개져 싸 보일 수 있음 | 스토어 스크린샷에 나오는 전설 8명과 아이콘부터 수작업 보정(아트 레인) |
| 후반 콘텐츠 부족 | 2\~3일차 이탈 | 환생·일일 퀘스트·도감을 출시판에 포함, 출시 후 D1·D7 리텐션 보고 다음 콘텐츠 결정 |
| 에이전트 코드의 구조 붕괴 | 수정할수록 느려짐 | 6장의 기계적 제약, 주 1회 정리 작업, QUALITY.md |
| 저사양 기기 발열·배터리 | 방치형은 켜두는 시간이 길다 | 화면 밝기·FPS를 낮추는 절전 모드(30fps 렌더, 로직은 그대로 20Hz) |
| iOS 비용 | 연 $99 | Android 지표 확인 후 가입. 코드는 처음부터 iOS 빌드까지 CI로 확인 |
| Codemagic 월 500분 | iOS 빌드 약 15\~25회 | iOS 빌드는 릴리스 태그에서만 실행 |
| Play 비공개 테스트 요건 | 신규 개인 계정이면 테스터 12명·14일 | 기존 계정 조건 확인. 필요하면 M4 기간에 걸쳐 진행 |

바다판으로 바뀌면서 더해진 리스크:

- **Pirate Busters와의 관계**: ‘방치형 외전’으로 확정(2026-10-13). 두 게임 모두 출시하고, 게임 안에 서로를 소개하는 배너를 둔다(광고비 0원 교차 홍보). 캐릭터 원본은 Pirate Busters가 기준이고, 원본이 바뀌면 도트를 다시 굽는다.
- **타격감과 성능**: 무리 14마리 + 이펙트 40개가 저사양 기기에서 프레임을 떨어뜨릴 수 있다. M2에서 저사양 기기 1대(예: 출시 4년 지난 보급형)로 60fps를 확인하고, 안 되면 상한을 낮춘다.
- **병렬 통합 비용**: 레인을 늘릴수록 머지·리뷰가 사람에게 몰린다. 동시 4개 상한과 매일 같은 통합 순서로 관리한다.
- **광고 제안 피로**: 하루 25회로 묶고 팝업을 쓰지 않지만, 버튼이라도 자주 보이면 피로가 쌓인다. 출시 후 장치별 시청률과 D1 리텐션을 함께 보고 빈도를 줄인다.

미결 사항 (결정되면 `docs/decisions/`에 ADR로 기록):

- [ ] 게임 이름과 패키지 ID 확정 (한국어는 ‘해적도트 원정대’, 영문 후보 ‘Pixel Pirate Raid’ 또는 ‘Dot Pirates: Idle Raid’. 패키지 ID는 기존 앱과 같은 접두어 + \`.piratedot\`)
- [ ] 화면 방향: 세로 고정으로 정함 (4.12). 태블릿은 전장·패널을 양옆으로 놓는 배치를 넣을지 미정
- [ ] 최소 지원 OS (Android 7.0 / iOS 13 제안)
- [x] 환생 해금 스테이지: 40으로 정함 (4.5)
- [x] 보스 재도전 광고 버프: 넣음 (4.6 함포 지원, 하루 10회)
